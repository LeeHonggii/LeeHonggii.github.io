처음엔 당연히 TF-IDF 벡터라고 생각했다. 키워드 기반 유사도라고 했고, IDF가 들어간다고 했으니까. 코사인 유사도 얘기인 줄 알았다.

아니었다.

---

## 키워드 태그는 "빈도" 데이터가 아니다

TF-IDF 코사인(cosine similarity) 방식은 문서를 고차원 벡터로 표현한다. 각 차원은 어휘 항목이고, 값은 해당 단어가 그 문서에서 얼마나 자주 나왔는지를 IDF로 보정한 수치다. 문서 안에서의 등장 횟수, 즉 TF(term frequency)가 출발점이다.

추천 시스템에서 다루는 콘텐츠 메타데이터는 구조가 다르다. 키워드 태그는 해당 콘텐츠에 "붙어 있냐 없냐"다. 같은 태그가 한 콘텐츠에 두 번 붙을 수 없다. TF가 항상 0 아니면 1이다. 문서 내 빈도라는 개념 자체가 성립하지 않는다.

그러니 TF-IDF 벡터를 쓰면 문제가 없는 게 아니라, 모델이 아예 틀린 가정 위에서 작동한다.

---

## 집합 비교가 맞다

키워드 태그가 집합(set)이라면, 두 콘텐츠의 유사도는 집합 비교로 계산하는 게 자연스럽다. 자카드(Jaccard) 유사도가 기본형이다.

```
자카드(A, B) = |A ∩ B| / |A ∪ B|
```

겹치는 태그 수를 전체 태그 수로 나눈다. 직관적이고 구현이 단순하다.

하지만 이대로 쓰면 "자바스크립트"처럼 수천 개 콘텐츠에 붙은 흔한 태그와, "특정 도메인의 희소한 전문 개념"처럼 몇 개 콘텐츠에만 붙은 태그가 동등하게 취급된다. 겹쳤을 때 정보량이 다른데, 점수에는 반영이 안 된다.

여기서 IDF가 들어온다.

---

## IDF 가중 자카드

IDF(inverse document frequency)는 어떤 태그가 전체 콘텐츠 중 얼마나 드물게 붙었는지를 수치화한다.

```
IDF(t) = log(N / df(t))
```

N은 전체 콘텐츠 수, df(t)는 태그 t가 붙은 콘텐츠 수다. 흔한 태그일수록 IDF가 낮고, 희소한 태그일수록 높다.

이 가중치를 자카드 계산에 얹으면 아래와 같아진다.

```
sim(A, B) = (Σ IDF(t) for t ∈ A∩B  +  ε)
           / (Σ IDF(t) for t ∈ A∪B  +  ε)
```

분자는 겹친 태그들의 IDF 합, 분모는 합집합 태그들의 IDF 합이다. ε(엡실론)은 분모가 0이 되는 상황을 막기 위한 스무딩(smoothing) 상수다. 코드에서 0.5를 쓰는 경우가 많다.

결과적으로 "희소한 전문 태그가 일치했을 때" 점수가 더 올라가고, "흔한 태그만 겹쳤을 때"는 점수가 상대적으로 낮게 유지된다. 이게 추천 맥락에서 원하는 동작이다. 희소하게 붙은 태그가 겹쳤다는 건 두 콘텐츠 사이에 의미 있는 공통점이 있다는 신호이기 때문이다.

---

## TF-IDF 벡터 방식과 비교해보면

TF-IDF 코사인 방식도 대조군으로 생각해볼 수 있다. 각 콘텐츠를 태그 어휘 크기의 벡터로 만들고(TF가 0/1이니 사실상 이진 벡터에 IDF를 곱한 것), 코사인으로 각도를 재는 방식이다.

수식으로 쓰면 결과가 비슷해 보이지만, 동작이 다르다. 코사인은 벡터의 방향을 본다. 이진 태그 벡터에서 코사인을 쓰면, 내적이 겹친 태그의 IDF 곱의 합이 되고 정규화 항이 각 콘텐츠의 IDF 제곱합 루트의 곱이 된다. 즉 태그 수가 많은 콘텐츠가 불리해지는 방향으로 정규화된다.

IDF 가중 자카드는 합집합을 분모로 쓰기 때문에 정규화 방식이 다르다. 태그가 많을수록 분모도 커지므로 태그 수 자체가 일정하게 패널티가 된다. 어느 쪽이 더 낫냐는 데이터 분포에 따라 다르지만, 집합 연산이라는 직관이 그대로 살아 있는 IDF 가중 자카드 쪽이 설명하기 쉽다. 면접에서 "왜 이 식이냐"고 물었을 때 대답하기 편한 식이다.

---
