임베딩 뽑고 코사인 재면 끝날 줄 알았다. 프로토타입은 그렇게 만들었고, 결과도 나쁘지 않았다. 무너진 건 결과가 아니라 질문 앞에서였다.

"이 콘텐츠가 왜 저 사용자한테 추천됐어요?"

0.73이라고 답할 수는 있는데, 그 0.73이 어디서 왔는지는 내가 봐도 모르겠더라.

## 네 개의 신호를 하나로 뭉치면

콘텐츠 하나에 붙어 있던 정보는 대충 이런 것들이었다.

- 키워드 리스트 — 집합에 가깝고, 대부분 희소하다
- 직무 코드 — `02 > 0201 > 020101` 처럼 계층이 있다
- 예상 학습 시간 — "30분 미만 / 30분~1시간 / …" 처럼 순서가 있는 구간
- 제목 — 자유 텍스트

이 네 개를 한 벡터로 인코딩해서 코사인을 재면, 각 신호가 원래 갖고 있던 성격이 다 뭉개진다. 직무 코드의 계층은 평평해지고, 학습 시간의 순서는 임베딩 좌표 어딘가로 흩어진다. "30분과 3시간은 멀다"는 정보를 모델이 알 방법이 없다.

더 곤란한 건, 방향 하나로 다 뭉뚱그려지니까 **왜 가까운지**를 분리해서 볼 수 없다는 것이었다. 키워드 때문인지, 제목 워딩 때문인지, 우연인지.

## 그래서 신호별로 따로 재기로 했다

식 자체는 별거 없다.

```
관련도 = Σ(신호 점수 × 가중치) / Σ가중치
```

이렇게 두면 코드는 좀 늘어나지만, 대신 신호마다 그 신호에 맞는 계산법을 쓸 수 있다.

**키워드**는 집합이니까 자카드가 더 자연스러웠다. 그런데 그냥 자카드는 "파이썬" 같은 흔한 단어와 어쩌다 겹친 희귀 키워드를 똑같이 취급한다. 그래서 IDF로 가중을 걸었다.

```
IDF(k) = log(N / df(k))

sim_kw = ( Σ IDF(k)  for k in A ∩ B  +  ε )
         ─────────────────────────────────
         ( Σ IDF(k)  for k in A ∪ B  +  ε )
```

`ε` 은 스무딩. 키워드가 거의 없는 콘텐츠끼리 붙었을 때 0/0 이 나는 걸 막는다. 값은 크게 중요하지 않아서 0.5 정도로 뒀다.

**직무 코드**는 문자열 유사도로 재면 안 된다. `020101` 과 `020102` 는 문자열로 보면 한 글자 차이지만 실제로는 같은 소분류 안의 형제고, `020101` 과 `030101` 은 문자열 유사도가 비슷해도 완전히 다른 대분류다. prefix 가 어디까지 일치하는지로 계단식 점수를 준다. 대분류 일치면 낮게, 소분류 완전 일치면 1.0.

**학습 시간**은 순서형 범주. 구간 중앙값을 뽑아 차이를 정규화한 뒤 거리 점수로 뒤집는다. 이건 굳이 벡터로 만들 이유가 없었다.

**제목**은 여기서만 임베딩을 썼다. 자유 텍스트라 다른 방법이 마땅치 않았다. 다만 임베딩은 **하나의 신호로만** 참여시켰다. 예전처럼 모든 걸 대변하는 대장이 아니라, 네 신호 중 하나.

## 이 방식이 실제로 편했던 건 디버깅이었다

가중합으로 만들어두면 결과 옆에 성분을 그대로 찍어볼 수 있다.

```
score = 0.61
 ├─ keyword     0.82  (w=0.35)
 ├─ ncs_prefix  0.40  (w=0.30)
 ├─ duration    0.90  (w=0.10)
 └─ title_emb   0.55  (w=0.25)
```

이렇게 나오면 "왜 이게 추천됐지?" 에 대답할 수 있다. "직무 코드 매칭이 약한데 키워드가 강하게 겹쳐서 올라왔다" 라고. 반대로 "직무는 딱 맞는데 왜 순위가 낮지?" 도 바로 보인다. 학습 시간이 튀거나 키워드가 하나도 안 겹쳤거나.

단일 벡터 코사인에서는 이 대화가 불가능했다. 0.73 은 그냥 0.73 이다.

## 가중치는 어떻게 정했느냐 하면

솔직히 말하면 처음엔 손으로 넣었다. 도메인상 직무 코드가 제일 중요할 것 같아 크게, 학습 시간은 튜닝용으로 작게. 이 초기값이 최적일 리 없다는 건 알고 있었다.

원래 계획은 클릭·완료율 같은 암묵 피드백으로 가중치를 회귀로 맞춰 보는 거였는데, 아직 거기까진 못 갔다. 로그가 쌓이는 속도가 생각보다 느렸고, 그 사이에 다른 우선순위가 끼어들었다. 이건 다음에 다시 볼 부분.

한 가지 확인하고 싶은 것도 남아 있다. 지금은 가중치가 사용자 세그먼트와 무관하게 전역이다. 신입 학습자와 경력 재교육자가 같은 가중치를 쓰는 게 맞는지, 아니면 세그먼트별로 갈라야 하는지 — 아직 재보지 않았다.
