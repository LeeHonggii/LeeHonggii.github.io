학습 활동 기록을 분석하는 LLM 리포트 파이프라인을 코드로 따라가던 중이었다. 비전 분석, 코드 계산, 평가, 서술 생성이 실제로 어떤 순서로 도는지 보는 작업이다. 그러다 질문이 하나 생겼다. 이 로그 대신 학생이 푸는 화면을 녹화한 영상을 넣으면 어떻게 될까.

아직 만들지 않았다. 영상 처리 코드도 프롬프트도 없고, 성능 수치도 없다. 이 글은 그 실험을 **무엇을 한 세트로 받아야 하는가**까지만 정리한 노트다.

## 기존 경로가 실제로 하는 일

기존 경로의 입력은 영상이 아니라 JSON이다. 활동 중 화면 상태가 프레임 단위로 저장되고, 각 프레임에는 화면 위 요소(`elements`)의 위치, 회전, 어느 칸에 붙어 있는지가 들어 있다. 분석 전에 먼저 이 기록을 텍스트로 바꾸는 코드가 있다. 그중 하나가 연속한 두 프레임을 비교해 "무엇이 어디서 어디로 갔는지"를 문장으로 뽑는 함수다. 식별자는 일반화해서 옮긴다.

```python
for a, b in zip(frames, frames[1:]):
    A = {e["id"]: e for e in a["elements"] if is_block(e)}
    B = {e["id"]: e for e in b["elements"] if is_block(e)}
    moves = Counter()
    for i, e in B.items():
        if i in A and where(A[i], names) != where(e, names):
            fit = ""
            if e.get("connectedBoardId"):
                fit = " [제자리]" if e.get("connectedBoardIdx") == unit(e) else " [다른 자리]"
            moves[f"{PLACE[unit(e)]} 모형: {where(A[i], names)} → {where(e, names)}{fit}"] += 1
    gone = Counter(PLACE[unit(e)] for i, e in A.items() if i not in B)
    new  = Counter(PLACE[unit(e)] for i, e in B.items() if i not in A)
    # ... 없어진 것/생긴 것을 "합치기"로 판정하고 한 줄로 출력
```

두 프레임에서 같은 `id`를 가진 요소의 위치를 비교하면 이동이 잡힌다. 한쪽에만 있으면 생성이나 소멸이다. 놓은 칸이 그 블록의 종류와 맞는지도 이 시점에 판정해서 `[제자리]` 같은 라벨을 붙인다. 결국 이 코드가 하는 일은 모델이 읽기 전에 **사실을 미리 확정해 두는 것**이다.

판정 규칙은 범용 쪽으로 한 단계 더 나아가 있다. 규칙 JSON을 받아 프레임마다 조건을 계산하고, 조건 종류별로 분기하는 구조다.

```python
def value(self, cond):
    t = cond["type"]
    if t == "group_shape_equals_group":
        start, gs = self.groups0()
        now = self.cells(self.f)
        a = [now[i] for i in gs[cond["group"] - 1] if i in now]
        return canon(a) == canon([start[i] for i in gs[cond["target"] - 1]])
    if t == "group_moved_count":
        start, gs = self.groups0()
        now = self.cells(self.f)
        return sum(1 for i in gs[cond["group"] - 1] if now.get(i) != start.get(i))
    if t == "items_created":
        ids0 = {e.get("id") for e in self.f0}
        return sum(1 for e, _ in boxes(self.f, self.s["item"]) if e.get("id") not in ids0)
    # ... support_counts, stick_number, sticks_moved 등
    raise ValueError(t)
```

도형이 시작 때 이웃한 칸끼리 어떻게 묶여 있었는지를 8방향 flood fill로 구하고, 지금 모양이 목표 묶음과 같은지를 정규화(`canon`)해서 비교한다. 이 로직은 좌표가 정확히 있어야 성립한다.

## 영상이 되면 무엇이 사라지나

위 두 블록은 전부 구조화된 상태를 전제로 한다. 요소 id가 있어서 "같은 블록"을 추적할 수 있고, 좌표가 있어서 칸 판정이 되고, 프레임 순서가 곧 시간이다. 영상에는 이게 하나도 없다. 픽셀이 있을 뿐이다. 블록이 같은 블록인지, 칸에 정확히 들어갔는지는 모델이 눈으로 추정해야 한다.

그래서 영상 실험은 기존 파이프라인의 변형이 아니라 **별개의 실험**으로 두기로 했다. 같은 리포트가 나오더라도 입력 성질이 다르면 한쪽을 다른 쪽의 대체재로 읽을 수 없다. 기존 경로는 코드로 사실을 확정한 뒤 모델에게 서술을 맡기는 구조이고, 영상 경로는 모델이 사실 확정까지 직접 해야 한다. 이 차이를 하나의 비교로 뭉개면 무엇이 좋아졌고 나빠졌는지 말할 수 없다.

## 한 세트를 어떻게 자를까

작은 비교 실험이라서 데이터 단위부터 정해야 했다. 제안한 건 이렇다.

```text
1세트 = 학생 1명 × 문항 1개
  ├─ 문항 이미지
  ├─ 정답 이미지
  └─ 풀이 영상 (시작 ~ 제출, 무편집)

흐름: 문항 이미지 + 정답 이미지 + 풀이 영상
      → 프레임 시퀀스 → LLM 분석 → 리포트
```

"무편집"을 조건으로 넣은 이유가 있다. 잘린 영상에서는 막혔던 시간이나 되돌린 흔적이 사라지고, 그러면 "풀이 과정"을 분석한다는 전제가 깨진다. 정답 이미지를 함께 받는 이유는 기존 경로의 규칙 JSON이 하던 역할(목표가 무엇인지)을 영상 쪽에서는 이미지로 대신 줘야 하기 때문이다.

영상은 모델에 그대로 넣지 않고 프레임 시퀀스로 바꿔서 넣는 쪽으로 제안했다. 여기서 막혔다. 프레임을 일정 시간 간격으로 뽑을지, 장면이 바뀔 때만 뽑을지가 정해지지 않았다. 간격이 좁으면 비용이 늘고, 넓으면 짧은 조작을 놓친다. 장면 변화 기반은 화면 대부분이 정지해 있는 풀이 화면에서 어떻게 동작할지 짐작이 안 간다. 이건 후속 설계로 남겼다.

## 샘플 수는 목적이 둘이다

수집 요구를 정리하다가 "샘플이 몇 개 필요하냐"는 질문이 사실 두 가지를 섞고 있다는 걸 알았다.

- 활동 **유형별**로 하나씩: 유형마다 영상 입력이 동작하는지 보는 용도다. 학생 수는 1명이어도 된다.
- 한 **과제당 여러 학생**: 또래와 비교하는 서술을 만들 수 있는지 보는 용도다. 이쪽은 같은 문항에 여러 명이 필요하다.

둘을 한 요청으로 합치면 어느 쪽도 충분하지 않은 데이터가 온다. 먼저 유형별 동작 확인 쪽을 요청하는 게 맞아 보인다.

## 아직 모르는 것

이번에 확인된 건 방향과 수집 조건까지다. 영상 입력이 로그 기반 입력만큼 정확한지는 재보지 않았다. 프레임 간격에 따른 비용과 누락도 마찬가지다.

또 하나 걸리는 게 있다. 기존 경로를 조사하면서 시험 데이터가 섞여 있거나 기록이 누락된 경우를 발견했다. 영상 쪽은 이런 문제를 사전에 걸러낼 장치가 없다. 비교 실험을 하려면 같은 학생·같은 문항에 대해 로그와 영상이 둘 다 있어야 하는데, 이 쌍을 안정적으로 모을 수 있는지는 아직 알아보지 않았다.
