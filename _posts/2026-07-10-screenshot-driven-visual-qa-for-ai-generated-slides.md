AI에게 HTML 슬라이드를 만들어달라고 시키면 코드는 늘 그럴듯하게 나온다. 문법도 맞고 클래스 이름도 자연스럽다. 문제는 브라우저를 켜는 순간 시작된다. 카드 높이가 제각각이고, 긴 텍스트가 카드 밖으로 삐져나오고, 섹션 사이 여백이 어떤 곳은 넓고 어떤 곳은 붙어 있다.

한동안은 그걸 코드로 되짚었다. "뭔가 이상한데." 그리고 다시 프롬프트를 넣었다. "레이아웃이 좀 이상해요, 다시 해주세요." 돌아온 코드는 거의 똑같았다. 당연했다. "이상하다"는 말은 아무것도 가리키지 않는다.

## AI는 자기가 만든 화면을 못 본다

이 당연한 사실을 자꾸 잊어버린다. 나는 화면을 보고 있고 AI는 코드만 있다. 내가 "이상하다"고 말할 때 머릿속에는 구체적인 그림이 있지만, 그 그림은 프롬프트를 타고 넘어가지 않는다. 넘어가는 건 "이상하다"라는 네 글자뿐이다.

그래서 워크플로를 바꿨다. 생성이 끝나면 코드부터 보지 않는다. 먼저 브라우저를 띄우고 스크린샷을 찍는다. 그 다음에 그 이미지를 보면서 스스로에게 묻는다. 같은 행의 카드가 같은 높이인가. 텍스트가 컨테이너 밖으로 나가진 않았나. 배경과 텍스트 대비가 읽을 만한가. 섹션 간 여백이 균일한가.

여기서 "아니오"가 나온 항목만 프롬프트로 옮긴다.

> "3번 카드가 2번 카드보다 낮아서 행 정렬이 깨진다. grid 행 높이 정렬 문제로 보인다. 여기만 다시 봐줘."

이 정도로만 좁혀도 다음 생성의 품질이 눈에 띄게 달라졌다. 범위와 가설, 이 둘이 붙어야 AI가 헛다리를 짚지 않는다.

## 카드 높이가 맞지 않는 두 가지 이유

반복적으로 마주친 문제는 카드 높이였다. 원인을 두 개로 나눠서 정리해뒀다.

하나는 grid 행이 콘텐츠에 맞춰 각자 높이를 갖는 경우다.

```css
display: grid;
grid-template-columns: repeat(3, 1fr);
```

이렇게만 두면 같은 행의 카드끼리는 stretch로 맞춰지지만, 행 자체의 높이는 그 행에서 콘텐츠가 가장 긴 카드가 정한다. 카드 내부에서 flex로 요소를 쌓는다면 그 배분 규칙이 겉으로 드러나는 모양을 또 바꾼다. 코드만 봐서는 이게 문제인지 아닌지 짐작이 안 간다. 렌더된 화면에서 눈금 대듯 봐야 보인다.

다른 하나는 카드 푸터를 바닥에 붙일 때 놓치기 쉬운 구조다.

```css
.card {
  display: flex;
  flex-direction: column;
}
.card-footer {
  margin-top: auto;
  flex: 0 0 auto;
}
```

`margin-top: auto`로 푸터를 바닥으로 밀고, `flex: 0 0 auto`로 푸터가 줄어들지 않게 잡아둔다. 이 두 줄 중 하나라도 빠지면 카드마다 푸터 위치가 다르게 나온다. 이것도 스크린샷을 봐야 티가 난다.

텍스트 넘침도 비슷하다.

```css
.card-body {
  overflow: hidden;
}
```

이 한 줄이 빠져 있으면 카드 경계 밖으로 문장이 흘러나온다. 그런데 데이터에 따라 어떤 카드에서만 발생하니까, 코드만 훑어서는 있는지 없는지 알 방법이 없다.

## 처음부터 다시 할 때는 실패 목록을 같이 넘긴다

부분 수정을 이어붙이다 보면 어느 순간 서로 충돌해서 레이아웃 전체가 흐트러진다. 그럴 때는 "처음부터 다시"가 답인데, 여기서 또 한 번 실수한 적이 있다. 그냥 "처음부터 다시 만들어줘"라고만 하면 같은 실수를 그대로 반복한다. AI 입장에서는 지난 시도에서 뭐가 문제였는지 모르니까 자연스러운 결과다.

그래서 다시 시킬 때는 스크린샷에서 잡아낸 문제들을 목록으로 붙였다.

> 이전 시도에서 이런 문제가 있었다:
> - 3열 카드의 두 번째 행에서 높이 불균형
> - 카드마다 푸터 위치가 다름
> - 좁은 카드에서 헤더가 2줄로 넘침
>
> 이 세 가지가 안 생기는 구조로 다시 설계해줘.

이렇게 넘긴 재설계는 처음부터 훨씬 나은 지점에서 출발했다. 실패의 원인을 언어로 옮겨서 넘기는 것과, 그냥 "잘 안 됐으니까 다시"라고 넘기는 것의 차이가 컸다.

## 아직 자동화하지 못한 부분

여기까지 오면 자연스럽게 다음 질문이 생긴다. 스크린샷 찍고 문제를 언어로 옮기는 이 과정도 자동화할 수 있지 않을까. Playwright로 화면을 찍고 렌더 결과를 다시 AI에게 다시 넘겨서 스스로 진단하게 하는 루프. 얼개는 그려지는데 아직 안정적으로 돌리진 못했다. 무엇을 봐야 하는지를 사람이 목록으로 넣어주지 않으면 AI가 화면을 봐도 엉뚱한 걸 지적한다. "이 카드가 조금 커 보인다" 같은 관찰이 돌아오는데, 그건 내가 원래 하던 "좀 이상해요"와 다르지 않다.

체크리스트를 어디까지 세밀하게 짜야 이 루프가 사람 손을 덜어주는지, 아직 감이 안 잡힌다. 이건 다음에 붙잡을 문제로 남겨뒀다.
