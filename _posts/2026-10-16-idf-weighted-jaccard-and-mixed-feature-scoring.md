추천 시스템의 메타데이터 처리와 점수 계산을 발표 도식과 코드에 맞춰 보다가 막힌 데가 있었다. 도식에는 "태그는 IDF로 가중한다"고 적혀 있었다. 그런데 설명하는 사람(나)도 듣는 사람도 머릿속에서는 "IDF = TF-IDF = 벡터로 만들어 코사인"으로 이어지고 있었다. 코드가 하는 일은 그게 아니었다. 새로 만든 건 없다. 이미 있는 구현을 확인하고, 틀리게 설명하던 부분을 바로잡은 기록이다.

## IDF는 벡터 전용이 아니다

IDF(Inverse Document Frequency, 역문서빈도)는 어떤 어휘가 얼마나 드문지를 나타내는 값이다. 전체 문서 수 N과 그 어휘가 나온 문서 수 df만 있으면 계산된다.

```
IDF = log(N / df)
```

거의 모든 문서에 붙은 태그는 값이 0에 가깝고, 몇 개 문서에만 붙은 태그는 값이 크다. 여기까지는 "희소도 측정"일 뿐이다. 이 값을 어디에 쓰느냐는 별개다. TF-IDF는 TF(어휘가 한 문서 안에서 나온 횟수)와 IDF를 곱해 문서를 벡터로 만들고 코사인으로 비교하는 하나의 조합이다. IDF를 쓴다고 이 조합이 따라오지는 않는다.

## 태그 집합에는 TF가 의미 없다

우리 데이터의 태그는 한 콘텐츠 안에서 중복되지 않는다. 같은 태그가 세 번 붙는 일이 없다. TF는 있거나 없거나 둘 중 하나(0/1)로 굳는다. 곱할 빈도 정보가 없으니, TF-IDF 벡터의 TF 쪽은 사실상 장식이 된다.

그래서 집합 비교인 자카드(Jaccard)에 IDF를 얹는 쪽이 자연스럽다. 일반 자카드는 공유 태그 수를 합집합 크기로 나눈다. 모든 태그를 같은 무게로 센다는 뜻이다. 여기서 개수 대신 IDF 합을 쓴다.

```
IDF 가중 자카드 = 공유 어휘의 IDF 합 / 합집합 어휘의 IDF 합
```

흔한 태그를 같이 가졌다는 건 약한 증거고, 드문 태그를 같이 가졌다는 건 강한 증거다. 이 직관이 분자와 분모에 그대로 들어간다.

계산이 맞는지 보려고 가상 예시를 만들었다. 실제 데이터 값이 아니라 산수 확인용이다.

- 전체 문서 N = 100
- 콘텐츠 A의 태그: 도형, 각도, 삼각형
- 콘텐츠 B의 태그: 도형, 각도, 원
- df: 도형 50, 각도 20, 삼각형 5, 원 10

자연로그로 IDF를 구하면 도형 0.693, 각도 1.609, 삼각형 2.996, 원 2.303이다. 공유 태그(도형, 각도)의 합은 2.302다. 합집합 네 개의 합은 7.601이다. 결과는 0.303이다. 일반 자카드라면 2/4 = 0.5다. 흔한 태그 위주로 겹치면 점수가 깎인다는 게 숫자로 보인다.

## 두 방식 중 뭐가 낫냐는 아직 재보지 않았다

헷갈리기 쉬운 지점이 하나 더 있다. "TF-IDF 벡터 코사인은 이 데이터에 안 맞는다"까지는 말할 수 있다. 그 말이 "벡터 표현은 한계가 있다"로 번지면 틀린 일반화가 된다. 한계가 있는 건 중복 없는 태그를 단순 TF-IDF로 벡터화하는 경우다. 임베딩 같은 다른 벡터 표현까지 싸잡을 이유는 없다.

같은 이유로, IDF 가중 자카드가 TF-IDF 코사인보다 추천 품질이 좋다는 주장도 하지 않는다. 둘을 같은 데이터에 놓고 비교한 적이 없다. 지금 내가 말할 수 있는 건 "이 데이터의 성격상 자카드 쪽이 설명이 자연스럽다"까지다.

## 태그는 신호 중 하나일 뿐이다

콘텐츠 사이의 관련도는 태그 하나로 정해지지 않는다. 속성의 종류가 다르다.

- 계층형 코드: 상위 분류가 같은지, 어디까지 같은지
- 시간 구간: 대상 구간이 얼마나 겹치는지
- 태그 집합: 위의 IDF 가중 자카드

종류가 다르니 점수를 내는 방식도 다르다. 계층 코드는 공통 접두 깊이로, 시간 구간은 겹침 비율로, 태그는 자카드로 각각 0~1 사이 점수를 낸다. 이걸 한 벡터에 밀어 넣지 않고 속성별로 따로 채점한 뒤 합친다.

```
기본 관련도 = Σ(신호별 점수 × 가중치) / Σ가중치
```

가상 예시로 보면, 신호 점수가 0.8, 0.3, 0.5이고 가중치가 3, 1, 2일 때 (2.4 + 0.3 + 1.0) / 6 ≈ 0.617이다. 분모를 가중치 합으로 나누기 때문에 가중치를 얼마로 두든 결과는 0~1에 머문다. 어떤 신호를 더 믿을지는 가중치만 바꿔서 목적에 맞게 조정할 수 있다. 벡터 하나로 합쳤다면 이 조정이 훨씬 어렵다.

## 부스팅과 RRF는 이 위에 얹힌다

기본 관련도 위에는 진행 조건에 따른 부스팅이 있다. 사용자가 어디까지 진행했느냐에 따라 점수를 올리는 층이다. 이 글에서는 조건의 세부를 다루지 않는다.

여러 추천 순위를 하나로 합칠 때는 RRF(Reciprocal Rank Fusion, 순위 역수 합산)를 쓴다. 점수 스케일이 서로 다른 목록을 합칠 때 점수 대신 순위만 쓴다는 점이 장점이다.

```
RRF 점수 = Σ 1 / (k + rank)
```

가상 예시로 k = 60이고 어떤 항목이 목록 A에서 1위, 목록 B에서 3위라면 1/61 + 1/63 ≈ 0.0323이다. 한 목록에서만 높은 항목보다 두 목록에서 고르게 높은 항목이 위로 올라온다. k 값은 일반적으로 쓰이는 값을 예로 든 것이다. 우리 구현에서 어떤 값을 쓰는지는 이 글에서 확정해 말하지 않겠다.

## 남은 것

발표 도식의 "IDF" 표기는 "IDF 가중 자카드"로 고쳐야 한다. 그다음에 실제로 하고 싶은 건 비교 실험이다. 같은 태그 데이터로 TF-IDF 코사인과 IDF 가중 자카드의 상위 추천을 뽑아 서로 얼마나 다른지 먼저 보려 한다. 다만 무엇을 정답으로 볼지는 아직 정하지 못했다.
