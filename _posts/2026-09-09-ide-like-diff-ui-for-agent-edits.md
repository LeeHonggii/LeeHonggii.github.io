AI 에이전트가 파일을 수정할 때마다 로그가 찍힌다. 처음엔 그 로그를 그냥 목록으로 뿌렸다.

"Edit 호출됨 — `utils.py`"  
"Edit 완료 — `utils.py`"

이게 한 파일당 두 줄씩 쌓인다. 에이전트가 10개 파일을 건드리면 20줄. 어느 게 전이고 어느 게 후인지 구분도 안 된다. 이벤트 스트림을 보고 있는 건지 에러 로그를 보고 있는 건지.

---

Claude SDK는 도구 호출에 `PreToolUse`와 `PostToolUse` 두 종류의 이벤트를 내보낸다. 하나는 실행 직전, 하나는 실행 직후. 같은 호출인데 카드가 두 장 생기는 문제를 먼저 잡아야 했다.

해법은 fingerprint였다. 두 이벤트를 묶을 키가 필요한데, SDK가 고유 ID를 안 주는 경우가 있어서 직접 만들었다.

```
fingerprint = md5(TOOL_NAME + JSON.stringify(INPUT))
```

도구 이름과 입력 내용을 합쳐 해시를 뽑으면, `PreToolUse`가 들어올 때 카드를 만들고 `PostToolUse`가 같은 fingerprint로 오면 그 카드를 덮어쓴다. 카드 수가 절반으로 줄었다.

단, 같은 도구를 같은 인자로 두 번 호출하는 경우엔 충돌한다. 실제로 에이전트가 같은 파일을 두 번 편집하는 패턴이 있어서, fingerprint에 호출 순서 카운터를 섞는 방식으로 해결했다. 완전한 해법은 아닌데, 실용적으로는 이 정도면 충분했다.

---

카드를 만들었으면 그 안에 뭘 보여줄지가 문제다.

처음엔 "파일명 + 도구 이름" 만 적었다. 클릭하면 전체 diff를 펼치는 구조. 그런데 에이전트가 파일 30개를 수정하면 다 열어봐야 뭘 했는지 안다. 전체 diff를 보기 전에 "이 카드가 중요한가"를 판단할 방법이 없었다.

`_extractChangePreview()`를 만들었다. 카드를 펼치지 않아도 핵심 변경 라인이 미리 보이도록. 로직은 간단하다 — diff에서 추가/삭제 라인만 추려서, 앞뒤 context를 최소한으로 붙여 카드 하단에 인라인으로 뿌린다. 3~5줄 정도.

이게 생각보다 판단 속도를 많이 올렸다. "함수 시그니처가 바뀌었네" 또는 "import 하나 추가한 거구나"를 카드만 봐도 알 수 있으면, 전체를 열어볼 카드가 절반 이하로 줄어든다.

---

diff를 보여줄 때 코드 하이라이팅이 없으면 Python 코드도 그냥 흰 텍스트로 보인다. Prism.js를 쓰고 있었는데, 언어를 자동 감지 못 하거나 번들에 해당 언어 팩이 없는 경우가 있었다.

그래서 fallback으로 `_simpleHighlight()`를 regex 기반으로 직접 짰다. 키워드, 문자열 리터럴, 주석 정도만 잡는다. 완벽하진 않지만 "완전히 안 되는 것"보다는 낫다. Prism이 언어를 인식하면 Prism이 이기고, 아니면 regex가 받는다.

compact diff 스타일도 따로 잡았다. 일반 GitHub diff 스타일은 라인 높이가 넉넉해서 200줄짜리 변경을 보려면 스크롤이 길어진다. 에이전트 로그는 동시에 여러 파일 변경이 쌓이는 특성이 있어서, 카드 하나의 세로 길이를 줄이는 게 중요했다. 폰트 사이즈를 1~2px 줄이고 줄 간격을 좁혔다. 단 삭제 라인(`-`)은 배경색이 더 진하게, 추가 라인(`+`)은 더 옅게 — 시선이 먼저 삭제 쪽으로 가게 의도했다.

---

아직 해결 못 한 부분이 하나 있다. `_extractChangePreview()`가 추출하는 "핵심 라인"이 항상 핵심이 아니다. diff 크기가 크면 앞부분 라인만 보여줘서, 실제로 중요한 변경이 파일 아래쪽에 있으면 미리보기에 안 잡힌다. 변경된 라인 중 어느 게 더 "의미있는" 변경인지를 판단하는 게 필요한데 — 단순 텍스트 diff로는 한계가 있고, AST를 파서로 보는 건 언어마다 달라서 범용으로 만들기가 쉽지 않다. 지금은 그냥 diff 앞부분이 보인다.
```
