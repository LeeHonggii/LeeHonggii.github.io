처음에는 단순했다. 콘텐츠를 오래 들을수록 레벨이 오른다. 학습 시간을 XP로 환산하고, XP가 쌓이면 레벨이 붙는다.

그걸 복잡하게 만든 건 나였다.

---

## 긴 영상 몇 개로 급승급하는 문제

학습자 레벨링을 처음 설계할 때 순수 학습 시간만 보면 된다고 생각했다. 30시간짜리 자격증 과정 하나를 완주하면 30시간만큼 XP가 쌓이고, 레벨이 오른다. 직관적이다.

문제는 실제 데이터를 보고 나서 생겼다. 콘텐츠 pool 안에는 3~5분짜리 단편 영상과 4~6시간짜리 장편 강좌가 공존한다. 장편 강좌 하나를 완료하면 단편 50개를 완료한 것과 같은 XP가 쌓인다. "콘텐츠를 얼마나 다양하게 경험했는가"라는 신호가 시간 단독으로는 잡히지 않는다고 판단했다.

그래서 콘텐츠 건수 관문을 추가했다. 특정 레벨 구간에 진입하려면 누적 학습시간뿐 아니라 일정 건수 이상의 콘텐츠를 완료해야 한다는 조건이었다.

---

## 이중 조건이 직관적이지 않다는 피드백

관리자 화면에서 학습자 프로파일을 볼 때 레벨 옆에 표시되는 상태 정보가 있다. "현재 레벨 도달 조건 중 건수 조건 미충족" 같은 문구가 나왔다.

운영 담당자 입장에서는 헷갈렸다. 학습 시간은 충분한데 왜 레벨이 안 오르는가. 장편 강좌 위주로 학습해온 사람이라면 시간은 많은데 건수가 부족한 상태가 자연스럽게 발생한다. 그게 "학습 부족"처럼 보이는 건 설계 의도와 달랐다.

더 근본적인 문제는, 건수 관문이 *추천 시스템의 입력*으로도 쓰이고 있다는 점이었다. 레벨 판정에 건수가 들어가면, 건수를 채우기 위한 단편 콘텐츠 추천 압력이 생긴다. 학습 목적과 무관한 short-form 콘텐츠가 레벨업을 위한 수단으로 소비될 수 있다.

폐지하기로 했다.

---

## 단순화: 10분 = 1 XP

기준을 하나로 줄였다. 학습 시간만 본다. 10분 학습이 1 XP다.

```python
def xp_gain_history(h: dict) -> float:
    return learning_minutes(h) / 10.0
```

`h`는 개별 학습 이력 레코드다. `learning_minutes`는 실제 시청/수강 시간을 분 단위로 환산한다. 완료 여부와 무관하게 시간 자체를 쌓는다. "완료해야 XP 지급"이 아니라 "보는 만큼 쌓인다"는 구조다.

경력 구간별 보정은 별도 상수로 관리한다. 경력이 길수록 기존 역량을 인정해 초기 XP를 더 얹어주는 방식이다.

```python
CAREER_PROFILE_XP_BONUS = {
    '4~7년':   4.0,
    '8~10년':  8.0,
    '11년 이상': 14.0,
}
```

경력 정보가 있는 학습자는 가입 시점에 이 보너스를 초기 XP로 받는다. 신입 학습자와 10년차가 같은 레벨에서 시작하는 걸 막기 위해서다.

## 로그 곡선: 초반은 빠르고, 후반은 완만하게

레벨 상한은 Lv 250으로 잡았다. 만렙까지 선형으로 가면 후반부에서 레벨업이 너무 드물어진다. 반대로 초반부터 너무 느리면 동기 부여가 안 된다.

로그 곡선으로 해결했다.

```python
import math

MAX_LEVEL = 250

def xp_to_level(xp: float) -> int:
    if xp <= 0:
        return 1
    level = MAX_LEVEL * math.log(1 + xp / MAX_LEVEL) / math.log(2)
    return max(1, min(MAX_LEVEL, math.floor(level)))
```

`floor(250 × ln(1 + XP/250) / ln2)` — XP가 250일 때 레벨 1, XP가 늘수록 곡선이 완만해진다. 초반 몇십 시간 학습으로 레벨이 빠르게 오르고, 고레벨로 갈수록 레벨업에 필요한 학습량이 커진다.

엔진 코드 안에는 `LEVEL_XP_NORM = 18.0`이라는 상수가 있다. 추천 점수 계산 시 레벨 기반 신호를 0~1 범위로 정규화할 때 쓰는 나눗값이다. 레벨 자체를 추천 가중치로 쓸 때 이 값으로 스케일을 맞춘다.

## 아직 확인 못 한 것

건수 관문 폐지 이후 학습자 레벨 분포가 실제로 어떻게 바뀌었는지는 아직 재보지 않았다. 장편 콘텐츠 위주 학습자의 레벨이 올라가는 건 의도한 대로지만, 그게 추천 결과의 다양성에 어떤 영향을 미치는지는 데이터로 확인이 필요하다.

또 하나 — 로그 곡선의 파라미터(`MAX_LEVEL = 250`)는 경험적으로 잡은 값이다. "250시간 학습 시 레벨 250 도달"이 직관적이어서 골랐는데, 실제 학습자 분포에서 어느 레벨에 몇 퍼센트가 몰리는지는 아직 열린 질문으로 남아 있다.
