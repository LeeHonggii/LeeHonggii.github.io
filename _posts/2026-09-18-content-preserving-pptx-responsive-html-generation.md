발표자료를 만들 때마다 같은 선택을 반복했다. PowerPoint를 열면 슬라이드마다 직접 붙여 넣고, HTML로 만들면 디자인을 따로 작업해야 했다. 소스가 둘이 되는 순간 어느 쪽이 최신인지 모르게 된다.

Markdown 하나를 원본으로 두고 PPTX와 HTML을 동시에 뽑는 파이프라인을 만들기로 했다. 생각보다 어렵지 않은 문제처럼 보였는데, 실제로 부딪힌 지점은 다른 곳이었다.

---

## 내용 유실이 먼저 문제였다

처음 시도는 AI에게 Markdown을 넘기고 슬라이드에 맞는 분량으로 재작성하게 하는 것이었다. 결과는 예상 가능했다. 긴 문단은 요약됐고, 코드 블록은 잘렸고, 표는 핵심만 남겨진다는 명목으로 행이 사라졌다.

발표자료 생성 도구를 만들 때 가장 먼저 정해야 할 원칙은 **내용을 편집하지 않는다**는 것이다. 분량이 슬라이드에 맞지 않으면 슬라이드가 길어지면 된다. 삭제는 사람이 한다.

그래서 파이프라인의 역할을 명확히 나눴다. 원본 Markdown을 건드리지 않고, 슬라이드 경계만 삽입한다. 헤딩(`#`, `##`)과 수평선(`---`)을 기준으로 분할한다. 분할 이후 각 슬라이드 안의 내용은 그대로다.

---

## Marp를 공통 렌더러로 고른 이유

PPTX와 HTML을 같은 소스에서 뽑으려면 렌더러가 두 포맷을 모두 지원해야 한다. Marp(Markdown Presentation Ecosystem)는 CLI 하나로 두 결과를 만든다.

```bash
marp deck.md --pptx --output deck.pptx
marp deck.md --html --output index.html
```

동일한 `.md` 파일에서 실행한다. 슬라이드 내용이 달라질 여지가 없다.

Marp는 Markdown을 그대로 렌더링한다. 코드 펜스, 표, 긴 문장을 축약하지 않는다. 슬라이드가 넘치면 스크롤이 생기거나 폰트가 줄어들 수 있지만, 내용이 사라지지는 않는다. 이 동작이 필요했다.

---

## 디자인과 레이아웃을 분리한 이유

브랜드 디자인(색상, 폰트, 전체 테마)과 슬라이드 레이아웃(콘텐츠 배치 방식)을 같은 레이어에 두면 둘 중 하나를 바꿀 때 나머지가 함께 흔들린다.

색상 테마는 전역으로 관리한다. CSS 변수 한 곳에서 브랜드 컬러를 바꾸면 전체 슬라이드에 반영된다. 레이아웃은 슬라이드마다 개별로 선택한다.

Marp에서는 슬라이드에 HTML 주석으로 클래스를 붙일 수 있다.

```markdown
<!-- _class: layout-bento-grid -->
```

이 클래스가 해당 슬라이드에만 특정 CSS를 적용한다. 타이틀 슬라이드, 두 컬럼 비교, 벤토 그리드, 코드 중심 레이아웃을 각각 정의해두면 작성자는 이름만 고른다.

결과적으로 "브랜드를 바꾸고 싶다"는 요청과 "이 슬라이드 배치를 바꾸고 싶다"는 요청이 서로 다른 파일을 건드리게 된다. 충돌이 줄어든다.

---

## 검증 단계를 넣은 배경

파이프라인이 돌고 난 뒤 결과물에서 원본의 코드 블록이 빠진 적이 있었다. 특정 레이아웃 클래스와 충돌해서였는데, 눈으로 확인하기 전까지 몰랐다.

그 이후로 생성 후 검증 단계를 추가했다. 원본 Markdown에서 코드 펜스, 표, 특정 키워드의 등장 횟수를 세고, 결과 HTML을 파싱해 같은 요소가 있는지 대조한다. 100% 일치가 목표가 아니라, 명백한 유실을 잡는 것이 목표다.

완벽하지 않다. 렌더러가 요소를 다르게 표현하면 false positive가 나온다. 지금은 코드 블록 수와 표 수만 비교하고 있고, 긴 문단이 잘렸는지는 아직 잡지 못한다.

---

## 아직 해결 안 된 것

반응형 HTML은 브라우저에서 열면 잘 보이는데, 프린트 뷰에서 레이아웃이 무너지는 슬라이드가 몇 개 있다. Marp의 HTML 출력이 프린트 미디어 쿼리를 어떻게 처리하는지 아직 파악 중이다.

PPTX는 반대 문제가 있다. 한글 폰트가 임베딩되지 않아 다른 기기에서 열면 폰트가 깨진다. Marp의 PPTX 생성이 폰트 임베딩을 지원하는지, 지원한다면 어떤 옵션인지 확인이 필요하다.
