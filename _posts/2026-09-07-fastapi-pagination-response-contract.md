프론트엔드가 NestJS 기반이고 백엔드 일부가 Python FastAPI로 구성된 구조에서, 두 쪽 응답 모양을 맞추는 작업을 했다. 기능 변경이라기보다 계약 정리에 가까웠는데, 생각보다 판단할 지점이 몇 군데 있었다.

---

## status 필드를 지웠다

기존 응답에는 이런 구조가 있었다.

```
{ "status": "success", "data": [...] }
{ "status": "error", "message": "..." }
```

HTTP 200으로 오는데 body 안에 성공 여부가 또 있다. 프론트에서 `if (res.status === 'success')` 같은 분기를 두 번 해야 한다는 뜻이다. NestJS 쪽은 그냥 HTTP 상태코드를 쓰고 있었으니 이 패턴이 혼자 튀어 있던 셈이다.

바꾸는 방향은 단순했다. 성공이면 2xx, 실패면 4xx/5xx. body에서 `status` 키를 없애고 에러 응답은 `error_code`와 `error_detail`만 남겼다.

```
{ "error_code": "TEMPLATE_QUERY_ERROR", "error_detail": "..." }
```

FastAPI에서 에러를 `HTTPException`으로 올리면 자연스럽게 이렇게 된다. 원래 `status` 필드를 억지로 넣으려면 응답 모델을 따로 감싸야 했으니, 오히려 코드가 줄었다.

---

## totalCount / list 구조로

목록 응답은 원래 `count`와 `templates`였다. 필드 이름이 엔드포인트마다 달랐다. 어떤 곳은 `count`, 어떤 곳은 `total`. 페이지네이션을 붙이면서 NestJS 쪽 `PaginationDto` 형태인 `totalCount`와 `list`로 통일했다.

```
{
  "totalCount": 7,
  "list": [...],
  "main_tool": "..."
}
```

`main_tool` 같은 컨텍스트 키는 그대로 붙였다. 응답이 목록만 주면 프론트에서 어떤 필터로 조회했는지 다시 계산해야 하는 경우가 있어서다.

---

## offset이 행 번호가 아니라 페이지 번호였다

쿼리 파라미터 이름이 `offset`이라 처음에 SQL `OFFSET`처럼 행 기준으로 봤다. 그런데 프론트 쪽 사용 패턴을 보니 `offset=1`이 첫 페이지, `offset=2`가 두 번째 페이지였다. 1-based 페이지 번호였던 것이다.

`skip = (offset - 1) * limit`으로 계산하면 맞는다. 이름이 `offset`인데 의미는 `page`다. 이상하지만 이미 프론트와 약속이 된 파라미터라 이름을 바꾸지 않고 계산식만 맞췄다.

---

## ORDER BY RAND()에 페이지네이션을 붙이면

랜덤 추천 엔드포인트가 있었다. DB에서 랜덤으로 N개를 뽑아 내려주는 방식이다. 여기에 `totalCount / list` 형태 응답을 붙이는 요구가 왔다.

잠깐 멈췄다. 랜덤 정렬에 페이지네이션이 의미가 있나? 첫 페이지에서 본 항목이 두 번째 페이지에 또 나올 수 있고, 반대로 아예 안 나오는 항목도 생긴다. 페이지네이션의 전제가 깨진다.

요구사항을 다시 확인해보니, 페이지를 넘기는 UX가 아니라 응답 형태를 통일하는 것이 목적이었다. 그러면 결론은 간단하다. 랜덤 로직은 그대로 두고, 응답 모양만 `totalCount / list`로 맞춘다. `totalCount`는 실제 전체 행 수가 아니라 이번 요청에서 뽑은 수가 된다. 부정확하지만 계약 형태를 맞추는 것이 목적이었으니 타협했다.

이 타협이 나중에 문제가 될 가능성은 있다. 페이지 UX가 실제로 붙으면 다시 손봐야 한다.

---

## 테이블 rename 후 남아 있던 JOIN

별도로, DB 테이블 이름이 바뀐 뒤에도 오래된 이름이 쿼리에 그대로 남아 있던 부분을 발견했다. JOIN 절에 구 이름이 들어가 있었다. 실제로 쿼리를 실행해 결과를 확인한 뒤 수정해서 develop 브랜치에 반영했다.

이게 언제부터 있었는지는 확인하지 않았다. 해당 쿼리가 운 좋게 안 탔거나, 아니면 DB 레벨에서 별칭이 있거나 했을 것이다. 어느 쪽인지는 아직 확인하지 않았다.
