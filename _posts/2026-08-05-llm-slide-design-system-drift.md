브랜드 토큰을 프롬프트에 다 넣었다. 색상 세 개, 폰트 한 벌, 여백 규칙. 1920×1080 슬라이드를 HTML + inline CSS로 뽑아달라고 했다.

받은 코드를 열었다. 변수명은 멀쩡했다. `--color-primary`, `--font-display`, 내가 준 이름 그대로.

브라우저에서 열었다. 낯선 초록이 눈에 박혔다. 배경엔 점 그리드가 깔려 있었고, 카드는 붕 뜬 것처럼 그림자를 두르고 있었다. 내가 준 브랜드가 아니었다.

## 처음엔 내 프롬프트 문제인 줄 알았다

몇 번 더 돌렸다. 표현을 바꿔가며. "브랜드 가이드를 엄격히 지켜라", "지정 색상만 사용하라". 그때마다 결과물은 조금씩 다른 방향으로, 그러나 항상 **내가 준 팔레트와는 다른 곳**으로 향했다.

세 번째쯤 되니 패턴이 보였다. 튀어나오는 초록의 hex를 뒤져봤다. `#3ecf8e`. 어디서 많이 본 초록이다. Supabase 랜딩에서 봤던 그 초록. 점 그리드 배경도 마찬가지였다. Vercel, Linear, 요즘 SaaS 랜딩페이지에서 흔히 보이는 그것.

이건 내 실수가 아니었다.

## 모델은 보이는 걸 만드는 게 아니라 익숙한 걸 만든다

당연한 얘기인데 CSS 앞에선 자꾸 잊는다. 텍스트 예측기니까, 학습 데이터에서 자주 본 CSS 조합이 확률적으로 더 두껍게 박혀 있다. 요즘 웹에서 "예쁜 SaaS 랜딩" 코드가 얼마나 많이 인덱싱돼 있는지 생각해보면, 저 초록이 튀어나오는 게 오히려 자연스럽다.

내가 프롬프트로 준 토큰은 **규칙**이 아니라 **힌트** 정도로 처리된다. 문맥이 살짝만 흔들리면 익숙한 쪽으로 서서히 돌아간다. 이걸 어디선가 design drift(디자인이 표준 패턴 쪽으로 미끄러지는 현상)라고 부르는 걸 봤다.

실제 받은 코드에는 이런 줄이 섞여 있었다.

```css
section[data-idx="11"] .eyebrow {
  color: #171717;
  background: #3ecf8e;
}

.card-grid {
  background-image: radial-gradient(#ededed 1px, transparent 1px);
  background-size: 24px 24px;
}
```

CSS 변수는 상단에 잘 선언돼 있었다. 그런데 정작 컴포넌트 셀렉터에서는 하드코딩된 hex가 인라인으로 들어와 있다. 변수를 정의만 하고 안 쓴 것이다. 모델이 "토큰을 선언한다"는 관습은 배웠는데, "토큰을 소비한다"는 관습은 그 자리에서 지키지 않았다.

## 코드 리뷰로는 못 잡는다

이게 나에게 가장 뼈아팠던 지점이다.

diff만 봤다면 그냥 넘어갔을 것이다. 변수 이름 맞고, 문법 맞고, 파일 구조도 깔끔했다. LGTM 찍고 넘길 코드였다.

문제는 브라우저에서만 보인다. 렌더링된 픽셀을 눈으로 봐야만 "아 이거 우리 브랜드 아닌데" 소리가 나온다. **코드 검증과 시각 검증은 다른 축**이라는 걸 이때 처음 몸으로 알았다.

그래서 루프를 바꿨다. 생성 → 코드 리뷰가 아니라, 생성 → 브라우저 스크린샷 → 색상 확인. 지금은 Playwright로 자동화해두고 색상 팔레트에 없는 hex가 렌더링 결과에 등장하는지 감사하는 스크립트를 붙였다. 어떻게 붙였는지는 다음 글에 쓸 거다.

## 프롬프트를 다시 짰다

허용만 나열하는 게 잘 안 먹혔다. "이 세 색만 써"라고 해도 네 번째 색이 튀어나왔다.

효과가 있었던 건 **금지를 구체적으로 나열**하는 쪽이었다. 두루뭉술한 "브랜드에 맞게"보다, "`#3e`로 시작하는 초록 금지, radial-gradient 배경 금지, border-radius 16px 초과 금지" 쪽이 훨씬 잘 지켜졌다. 왜 그런지는 나도 정확히 모른다. 짐작으론 모델이 "무엇이 브랜드에 맞는가"를 판단하는 것보다 "이 패턴을 안 쓰는 것"을 실행하는 게 더 쉬운 태스크라서 그런 것 같다.

프롬프트 끝에 self-check(모델이 스스로 산출물을 검토하는 단계)도 붙였다.

```
생성 후 스스로 확인:
- 사용된 모든 hex가 허용 목록에 있는가
- background-image 속성에 gradient/pattern이 들어갔는가
- 셀렉터에서 하드코딩 hex를 쓴 곳이 있는가
하나라도 걸리면 다시 작성.
```

이걸 넣으니 첫 응답의 위반율이 눈에 띄게 줄었다. 정확한 수치는 재보지 않았다. 다만 두세 번씩 다시 시키던 게 한 번에 되기 시작했다.

## 아직 못 푼 것

가장 골치아픈 건 여백과 리듬이다. 색은 hex로 감사할 수 있고 폰트는 family로 잡을 수 있는데, "이 슬라이드가 우리 브랜드처럼 보이는가"의 절반은 여백에서 온다. 모델은 여기서 자꾸 SaaS 랜딩 리듬으로 미끄러진다. 큼직한 히어로, 중앙 정렬, 넉넉한 상하 패딩. 우리 브랜드는 그 리듬이 아니다.

이걸 어떻게 프롬프트로 잡을지, 아니면 아예 레이아웃은 코드로 고정하고 모델에겐 콘텐츠만 맡길지 아직 결론이 안 났다. 후자로 기우는 중이긴 하다.
