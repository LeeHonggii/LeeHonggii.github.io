push가 막혔다. 정확히는, 원격 저장소 자체에 접근할 수 없는 환경에서 커밋을 만들고, 그걸 접근 가능한 다른 환경으로 옮겨야 했다.

처음엔 간단한 일이라고 생각했다.

---

## 패치 파일로 커밋을 싸서 보낸다

`git format-patch`는 커밋을 `.patch` 파일로 직렬화한다. 이메일 기반의 고전적인 협업 방식에서 나온 도구인데, 지금도 원격 저장소 없이 커밋을 전달해야 할 때 유용하다.

```bash
git format-patch <base>..<end>
```

`<base>`부터 `<end>`까지의 커밋 범위를 각각 하나의 `.patch` 파일로 만든다. 파일 이름에 순번과 커밋 제목이 붙어서 순서가 보인다.

받는 쪽에서는:

```bash
git am test.patch
```

이걸로 커밋이 그대로 재생된다. diff만 적용하는 `git apply`와 달리 `git am`은 커밋 메시지, 작성자 정보까지 살려서 새 커밋을 만든다.

여기까지는 예상대로였다.

---

## 브랜치를 안 확인했다

문제는 `git am`을 실행하기 전에 어느 브랜치에 있는지 확인하지 않은 것이었다.

`git am`은 현재 체크아웃된 브랜치에 바로 커밋을 쌓는다. 돌아보면 당연한 동작인데, 패치를 적용하는 행위 자체에 집중하다 보니 브랜치 상태를 흘려봤다.

`git status -sb`를 먼저 실행했다면 한 줄로 확인할 수 있었다.

```bash
git status -sb
## main...origin/main
```

브랜치 이름이 첫 줄에 나온다. `-s`는 short format, `-b`는 브랜치 정보 포함이다. 짧고 명확하다. 이걸 습관처럼 실행하지 않았던 게 이번 혼란의 시작이었다.

엉뚱한 브랜치에 커밋이 쌓인 걸 발견하고 복구해야 했다.

---

## src refspec 오류와 로컬 브랜치

패치 적용 이후 push를 시도했더니 이번엔 다른 오류가 나왔다.

```
error: src refspec develop does not match any
```

`develop`이라는 이름의 로컬 브랜치가 없었다. 원격에는 존재하지만 로컬에 추적 브랜치가 만들어지지 않은 상태였다.

```bash
git branch -a
```

로 확인하면 `remotes/origin/develop`은 보이는데 `develop`은 없다.

```bash
git checkout -b develop origin/develop
```

이렇게 하면 원격 브랜치를 추적하는 로컬 브랜치가 생긴다. 이후 `git push origin develop`이 통했다.

다만 이 시점에서 커밋이 올바른 브랜치에 있어야 한다. 아까 엉뚱한 브랜치에 쌓인 커밋은 `git cherry-pick`으로 옮겼다.

```bash
git cherry-pick <커밋 해시>
```

cherry-pick은 특정 커밋의 변경 내용만 현재 브랜치에 새 커밋으로 복사한다. 브랜치를 통째로 merge하거나 rebase하지 않아도 되는 경우에 편하다.

---

## pre-receive 500은 별개의 이야기였다

push 과정에서 서버 쪽 pre-receive 훅이 500을 반환하는 오류도 있었다. 처음엔 로컬 브랜치 문제와 같은 선상에서 보려고 했는데, 원인이 달랐다.

로컬 `src refspec` 오류는 로컬 git 상태의 문제다. 브랜치가 없거나, 이름이 다르거나, 추적 설정이 안 된 것.

pre-receive 500은 서버 측 훅 스크립트의 문제다. push가 서버에 도달하긴 했지만 서버 쪽 검증 로직에서 예외가 발생한 것이다. 로컬에서 아무리 브랜치를 고쳐도 해결되지 않는다.

이번 경우엔 재시도로 push가 성공했다. 서버 훅이 외부 API를 호출하는 구조였고 일시적인 오류였던 것 같다. 하지만 왜 500이 났는지는 서버 로그를 직접 확인하지 않아서 정확히 모른다.

---

두 가지 오류를 연달아 만나다 보니 처음엔 연관이 있다고 생각했다. 분리해서 보는 게 늦었다. 오류 메시지를 다시 읽었을 때 "이건 클라이언트 쪽, 저건 서버 쪽"이라는 게 보였다.

pre-receive 훅이 어떤 조건에서 500을 내는지는 아직 확인하지 못했다.
