콘텐츠 수백 개에 키워드를 다시 붙이는 작업을 하다가 중간에 방향을 바꿨다. 처음엔 "잘 설명하는 단어"를 찾고 있었는데, 어느 순간 그게 추천에 아무 도움이 안 된다는 걸 알아버렸다.

## 시작은 반대 방향이었다

첫 배치를 돌릴 때 나는 콘텐츠 하나에 6~8개씩 키워드를 뽑고 있었다. 제목, 설명, 기존 태그를 다 보고 "이 강의를 가장 정확히 표현하는 단어들"을 골랐다. LLM한테도 그렇게 시켰다. 결과물은 그럴듯했다. "LLM 파인튜닝 실습" 강의에는 `파인튜닝`, `LoRA`, `QLoRA`, `PEFT`, `Hugging Face`, `GPU 최적화` 같은 것들이 붙었다. 콘텐츠 카드에 그대로 찍어도 손색 없어 보였다.

문제는 그다음이었다. 사용자 관심사 프로필과 매칭을 돌려보니 이 강의는 거의 아무한테도 안 걸렸다. 사용자 쪽 신호에는 `LoRA`나 `PEFT` 같은 단어가 애초에 존재하지 않았기 때문이다. 사용자는 자기 관심사를 그렇게 세밀하게 쓰지 않는다. `LLM`, `AI`, `파이썬` 정도로 쓴다.

즉 내가 뽑은 키워드는 **콘텐츠를 설명하는 데는 성공했지만, 콘텐츠와 사람을 잇는 데는 실패**하고 있었다.

## 설명과 매칭은 같은 일이 아니다

여기서 태깅의 목적을 두 개로 분리해서 봐야 했다.

- 설명(describe): 이게 뭔지 표현하기 → 특이하고 구체적인 단어가 좋음
- 매칭(match): 어떤 사용자와 이을지 결정 → 여러 콘텐츠·사용자 프로필이 공유하는 단어가 필요

추천에서 필요한 건 두 번째다. 첫 번째는 검색이나 상세페이지 몫이다. 둘을 한 필드(`keyword_tags`)에 우겨넣으면 매칭 신호가 롱테일로 분산되고, 어떤 콘텐츠는 세상에 하나뿐인 태그만 갖게 된다. 그런 태그는 매칭 그래프에서 고립된 점이다.

그래서 나는 목표를 뒤집었다. **콘텐츠당 2~3개.** 대신 그 2~3개는 반드시 다른 콘텐츠와 겹치는 단어여야 한다.

## 2~3개 규칙이 실제로 만든 판단

숫자만 정해두면 LLM은 여전히 아무 단어나 2개 뽑는다. 그래서 배치 프롬프트에 "이 콘텐츠와 최소 20개 이상의 다른 콘텐츠가 공유할 수 있는 상위 개념어를 우선한다"는 조건을 넣었다. 그리고 판단 근거로 세 입력을 같이 보게 했다.

| 입력 | 이걸로 판단하는 것 |
|---|---|
| 제목 | 이 콘텐츠의 축이 되는 개념 |
| 설명 | 축의 구체적 범위 |
| 기존 `keyword_tags` | 우리 태그 체계에 이미 존재하는 어휘인지 |

세 번째가 특히 중요했다. 새 단어를 매번 만들어내면 태그 사전이 무한히 부풀고, 매칭 대상 집합이 다시 잘게 쪼개진다. 기존 어휘를 재사용하는 걸 기본으로 두고, 정말 없을 때만 새 단어를 추가했다.

같은 "LLM 파인튜닝 실습" 강의에 다시 붙인 태그는 `LLM`, `파인튜닝` 두 개였다. 처음엔 이게 너무 성긴 것 같아 불안했는데, 매칭 결과를 보고 나서야 이게 정답이었다는 걸 알았다. 이 두 단어는 사용자 프로필에도, 다른 수십 개 콘텐츠에도 존재한다. 다시 말해 이 강의는 이제 그래프 위에서 다른 점들과 이어져 있다.

## 배치를 진짜 반영했는지 검증하는 부분

여기부터는 태깅 그 자체보다 파이프라인 이야기다. 수백 개를 LLM으로 처리하면 반드시 어딘가에서 하나씩 새거나 어긋난다. 나는 배치 결과를 이런 구조로 저장했다.

```
rematch_batches/<strand>_batchNN.json
```

```json
{
  "batch": "AI_데이터_batch01",
  "results": [
    { "cid": "content_001", "keywords": ["AI", "데이터"] },
    { "cid": "content_002", "keywords": ["머신러닝", "전처리"] }
  ]
}
```

이걸 소스 오브 트루스인 전체 메타데이터 JSON의 `keyword_tags` 필드에 덮어쓰는데, 반영 스크립트가 끝난 다음 항상 아래 한 줄을 확인했다.

```
result.json ↔ meta.json mismatch = 0
```

이 숫자가 0이 아니면 셋 중 하나다. cid 매핑이 틀렸거나, 배치 파일이 하나 누락됐거나, 덮어쓰기 순서가 뒤엉켜 나중 배치가 앞 배치를 지웠거나. 실제로 초반에 몇 번은 mismatch가 두 자릿수로 찍혔고, 매번 원인이 달랐다. 이 검증 한 줄이 없었으면 나는 "다 반영됐다"고 착각한 채 다음 단계로 넘어갔을 것이다.

## 아직 정리하지 못한 부분

매칭 신호 관점에서 2~3개는 지금까지는 잘 동작하고 있는데, 두 가지가 남아있다.

하나는 **너무 상위 개념만 남으면 매칭이 지나치게 넓어지는 문제.** `AI` 하나만 붙은 콘텐츠들은 서로 구분이 안 된다. 이건 랭킹 단계에서 다른 신호(수강 이력, NCS 코드, 시리즈 관계)로 갈라야 할 것 같은데, 어디까지가 태그의 책임이고 어디부터가 랭킹의 책임인지 아직 선을 못 그었다.

다른 하나는 **태그 사전을 어떻게 관리할지.** 지금은 배치가 끝날 때마다 새로 생긴 단어를 눈으로 확인하고 있는데, 이건 콘텐츠가 몇 천 개 넘어가면 못 한다. 신조어와 오타를 분리하는 규칙이 필요하고, 아마 그건 다음 strand 재검증 때 붙일 것 같다.
