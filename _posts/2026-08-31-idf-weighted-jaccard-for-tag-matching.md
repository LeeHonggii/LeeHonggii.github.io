태그 두 집합이 얼마나 비슷한지 재려고 했을 때, 처음 떠오른 건 TF-IDF 벡터였다.

추천 시스템을 만들면서 콘텐츠와 사용자 관심사를 키워드로 표현해야 했다. 키워드가 얼마나 겹치는지를 유사도로 쓰려면, 아무래도 익숙한 TF-IDF + 코사인 유사도 조합이 먼저 떠오른다. 검색 분야에서 수십 년 검증된 방법이고, 라이브러리도 많다.

그런데 멈추게 된 지점이 있었다.

---

## TF가 의미 없는 데이터

TF(Term Frequency)는 문서 안에서 단어가 몇 번 나왔는지를 센다. "경제"라는 단어가 한 기사에 20번 등장하면, 그 기사가 경제 주제임을 강하게 드러낸다는 논리다.

그런데 태그는 다르다. 태그는 보통 중복 없이 붙인다. `["파이썬", "머신러닝", "데이터분석"]` 같은 집합이다. "파이썬"이 이 집합에 두 번 들어갈 일이 없다. TF는 항상 0 아니면 1이다.

TF가 항등적으로 1인 데이터에 TF-IDF를 쓰면, 사실상 IDF만 남는다. 벡터 공간으로 임베딩해 코사인을 재도 결국 IDF로 가중한 겹침 비율을 측정하는 것과 크게 다르지 않다. 그렇다면 굳이 벡터화를 거칠 필요가 있을까.

---

## 단순 자카드의 문제

태그 집합 비교에는 자카드 유사도(Jaccard similarity)가 잘 맞는다. 정의가 직관적이다.

```
|A ∩ B| / |A ∪ B|
```

겹친 태그 수를 전체 태그 수로 나눈다. 그런데 이 방식엔 맹점이 있다. "파이썬"이 겹친 것과 "양자컴퓨팅"이 겹친 것을 같은 가중치로 센다.

전체 콘텐츠 데이터를 보면, 흔한 키워드와 희소한 키워드의 분포 차이가 꽤 크다. 누구나 붙이는 흔한 태그가 겹쳤다고 해서 두 콘텐츠가 비슷하다고 보기는 어렵다. 반대로 매우 드문 태그 하나가 일치했을 때는 그게 더 강한 신호다.

---

## IDF로 희소도를 가중한다

IDF(Inverse Document Frequency)는 어떤 태그가 전체 콘텐츠 중 얼마나 많은 곳에 등장하는지를 역수로 표현한다.

```
idf(t) = log(N / df(t))
```

N은 전체 콘텐츠 수, df(t)는 해당 태그가 붙은 콘텐츠 수다. 흔한 태그는 df(t)가 N에 가까워서 IDF가 낮아지고, 희소한 태그는 IDF가 높아진다.

이걸 자카드에 얹으면, 겹친 태그의 희소도 합을 전체 태그의 희소도 합으로 나누는 형태가 된다.

```
sim_kw = (Σ idf(t) for t ∈ A∩B + 0.5) / (Σ idf(t) for t ∈ A∪B + 0.5)
```

분자·분모에 0.5를 더한 건 BM25에서 빌려온 스무딩이다. 집합이 텅 비거나 극단적으로 작을 때 수치가 튀는 걸 막는다.

---

## 코사인과 비교해서 실제로 달랐나

솔직히 말하면, 정량 비교를 충분히 해보지 않았다. TF-IDF 벡터 코사인과 IDF 가중 자카드를 같은 입력에 돌려서 순위 차이를 체계적으로 재본 적이 없다.

설계 단계에서의 판단은 이랬다. 태그는 TF가 의미 없는 데이터고, 벡터화는 불필요한 단계를 추가하며, IDF 가중 자카드는 계산도 단순하고 해석하기도 쉽다. 이 조합이 더 낫다고 봤다.

다음에 실제로 재봐야 할 것은, 흔한 태그만 가진 콘텐츠 쌍과 희소한 태그가 하나 겹친 쌍을 놓고 두 방식이 순위를 얼마나 다르게 매기는지다. 특히 태그 수가 아주 적은 경우에 어느 쪽이 더 안정적인지는 아직 모른다.
