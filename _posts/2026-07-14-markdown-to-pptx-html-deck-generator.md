발표자료를 AI에게 맡기면 내용이 사라진다. 이걸 처음 알아챈 건, 원본 md에 공들여 넣어둔 비교 표가 슬라이드에서는 헤드라인 한 줄로 요약되어 있던 순간이었다. "핵심만 남겼습니다" 라는 친절한 코멘트와 함께.

문제는 두 겹이었다. 하나는 지금 말한 요약 손실. 다른 하나는 PPTX와 웹용 HTML을 따로 만드느라 소스가 두 벌이 된다는 것. 한쪽을 고치면 다른 쪽이 어긋난다. 발표 전날 밤에 이걸 두 번 반복하고 나서 접근을 다시 짰다.

## 왜 엔진을 두 개 쓰지 않기로 했나

처음 떠올린 건 `python-pptx` + `reveal.js` 조합이었다. PPTX 편집 자유도가 높고, HTML은 웹 배포에 유리하니까. 그런데 몇 시간 만져보고 접었다.

두 엔진을 유지한다는 건 슬라이드 분할 로직을 두 곳에 두는 것과 같다. "H2에서 슬라이드 나눔, 표는 독립 슬라이드" 같은 규칙을 양쪽에 심고, 테마 색을 양쪽에 맞추고, 이미지 경로도 양쪽에서 챙긴다. 결국 두 산출물이 미묘하게 달라진다. 어긋난 걸 발견하는 건 대개 발표 30분 전이다.

Marp는 하나의 `deck.md` 에서 두 포맷을 다 뽑는다.

```bash
marp deck.md --pptx
marp deck.md --html
```

명령 두 줄. 슬라이드 분할, 테마, 이미지 참조가 전부 md 한 파일에 모여있다. 편집 자유도는 좀 떨어지지만, 소스가 하나라는 이점이 그걸 눌렀다.

## 진짜 하고 싶었던 건 변환 규칙이었다

엔진 선택보다 훨씬 오래 붙잡은 건 "원본 → 슬라이드" 변환의 원칙이었다. AI든 스크립트든, 이 규칙을 지키게 만드는 게 이번 작업의 본체였다.

규칙은 한 줄이다.

> 원본 `source.md` 의 어떤 요소도 삭제하지 않는다. 슬라이드 분할(1:1 또는 1:N)만 허용한다.

세부 매핑은 이렇게 뒀다.

| 원본 요소 | 변환 |
|---|---|
| H2 | 새 슬라이드 시작 |
| 3줄 초과 문단 | 문단 단위로 분할 |
| 코드 블록 | 독립 슬라이드 1장 |
| 표 | 독립 슬라이드 1장 |
| H3 이하 | 같은 슬라이드 내 강조 |

"요약해서 슬라이드에 맞추기" 가 아니라 "그대로 옮기되 슬라이드를 더 나누기". 이 규칙을 프롬프트 앞에 못박아 두니까, AI가 표를 헤드라인으로 뭉개는 일이 눈에 띄게 줄었다. 아예 사라지진 않았다. 그래서 다음 단계가 필요했다.

## 산출물 옆에 원본을 남겨두는 이유

디렉터리는 이렇게 잡았다.

```
_decks/<slug>/
  deck.md
  deck.pptx
  index.html
  theme.css
  source.md
```

`source.md` 를 굳이 같이 두는 이유는 검증 때문이다. 산출물이 원본을 얼마나 지켰는지 사후에 재봐야 한다. 원본이 다른 곳에 있으면 이 대조가 귀찮아지고, 귀찮으면 안 하게 된다.

## 검증은 세 가지만 본다

전수 비교는 오버킬이었다. 실제로 사고가 나는 지점만 잡으면 된다.

- 코드 블록 개수가 원본과 일치하는가 (` ``` ` 카운트)
- 표의 `|` 행 합계가 원본 이상인가 (표가 통째로 날아간 경우를 잡는다)
- 원본에서 `**bold**` 로 강조한 문장이 슬라이드 어딘가에 등장하는가

이 세 가지만 자동 diff 로 돌려도, "슬라이드가 텅 비어있는" 최악의 사고는 거의 다 걸린다. 완벽하진 않다. 예를 들어 표의 내용은 그대로인데 셀 값이 뒤바뀌는 경우는 못 잡는다. 아직 이걸 잡는 좋은 방법을 못 찾았다.

## 남은 것

Marp 자체의 레이아웃 자유도는 여전히 답답하다. 특정 슬라이드만 2단으로 하고 싶다든가, 한 슬라이드 안에서 표와 그림을 좌우로 놓고 싶다든가 하는 게 CSS 우회로 되긴 하는데 지저분하다. 지금은 그런 슬라이드만 골라서 PPTX 후처리로 손을 대는 식인데, 이 예외가 늘어나면 결국 소스가 다시 두 벌이 된다. 그 경계선을 어디에 그을지는 아직 못 정했다.
