발표자료 초안을 AI에게 맡겼다가 원고 내용이 반쪽으로 줄어 있었던 경험이 있다. 내가 쓴 문장이 "비슷한 말"로 뭉뚱그려지거나, 코드블록이 그냥 사라지거나. 항의하면 "슬라이드는 간결해야 하지 않나요?" 라고 되돌아온다. 맞는 말이기는 한데, 간결함과 유실은 다르다.

그래서 방향을 바꿨다. AI가 내용을 **요약하지 못하도록** 구조적으로 막는 것.

---

## 핵심 제약: 분할만 허용한다

원고는 마크다운으로 작성한다. 슬라이드 변환에서 AI에게 허용하는 연산은 하나뿐이다. **분할(split)**. H1·H2 제목과 `---` 구분선을 기준으로, 원고의 섹션을 슬라이드 하나 혹은 여러 장으로 나누는 것만 된다.

요약은 안 된다. 재작성도 안 된다. 원고에 있는 단어는 슬라이드에 그대로 있어야 한다.

이렇게 하면 한 가지 문제가 생긴다. 원고에 5줄짜리 코드블록이 있으면 슬라이드에 5줄짜리 코드블록이 들어간다. 발표 덱치고 다소 무거울 수 있다. 그런데 그게 원고 작성자의 판단이다. 생략할 거면 원고에서 생략하면 된다. 도구가 대신 결정하게 두지 않는다.

---

## Marp를 고른 이유

Marp(마프)는 마크다운을 PPTX와 HTML 슬라이드로 변환해 주는 CLI 도구다. 같은 `.md` 소스에서 두 형식을 동시에 뽑을 수 있다는 점이 결정적이었다.

```
marp deck.md --pptx
marp deck.md --html
```

한 소스, 두 산출물. PPTX와 HTML이 서로 다른 원본에서 나오면 내용 불일치가 생길 수밖에 없다. 같은 파일에서 뽑으면 그 문제가 원천 차단된다.

테마는 CSS 한 파일로 관리한다. 컬러, 타이포, 간격을 CSS 변수로 선언해 두고 PPTX·HTML 양쪽이 같은 파일을 바라보게 한다. 덕분에 "PPTX는 파란데 HTML은 회색"인 상황을 피할 수 있다.

산출물 구조는 이렇게 잡았다:

```
_decks/<slug>/
  source.md      # 원고 (건드리지 않음)
  deck.md        # Marp 마크다운 (분할 결과)
  theme.css      # 테마
  deck.pptx
  index.html
```

`source.md`를 별도로 두는 이유는 재생성할 때 원고를 잃지 않기 위해서다. `deck.md`는 언제든 덮어써도 된다.

---

## 생성 후 검증

분할이 제대로 됐는지 확인하는 단계를 뒤에 붙였다. 검사 항목은 단순하다.

- 원고에 코드블록이 있으면 `deck.md`에도 있는가
- 원고에 표(table)가 있으면 `deck.md`에도 있는가
- 원고의 H1·H2 제목이 모두 슬라이드 어딘가에 나타나는가

이 검사를 통과하지 못하면 경고를 낸다. 산출물을 막지는 않는다. 발표자가 봐서 "이 코드블록은 슬라이드에 안 넣어도 된다" 싶으면 원고에서 직접 지우면 그만이다. 도구는 사실만 알려준다.

수치적으로 누락률을 재본 적은 없다. 검증 로직을 달기 전에 몇 번 생성해 봤을 때 체감상 빠진 게 없었는데, 그게 구조 덕분인지 그냥 원고가 짧아서인지는 아직 모른다.

---

## 아직 못 고친 것

HTML 덱의 레이아웃 문제가 남아 있다. Marp의 기본 HTML 출력은 슬라이드 비율이 고정돼 있어서 작은 화면에서 글자가 잘린다. CSS로 어느 정도 보완했는데 긴 코드블록이 들어간 슬라이드는 여전히 오른쪽이 잘리는 경우가 있다.

PPTX 쪽은 Marp가 렌더링 엔진을 가지고 있어서 CSS를 직접 건드리기가 어렵다. 현재는 생성 후 PowerPoint에서 직접 수정하는 걸 감수하고 있다.

레이아웃 템플릿을 슬라이드 유형별로 여러 개 두는 구조도 설계는 해뒀는데 아직 구현하지 않았다. "제목만 있는 슬라이드", "코드블록 중심 슬라이드", "2단 레이아웃 슬라이드"를 각각 다른 CSS 클래스로 처리하면 지금보다 레이아웃 유연성이 생길 것 같다는 생각인데, 실제로 써봐야 안다.
