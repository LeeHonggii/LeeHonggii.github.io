기술 사업계획서 초안을 AI에게 맡긴 적이 있다. 문장이 매끄러웠고 수치가 자연스럽게 자리 잡혀 있어서, 처음 받았을 땐 "이 정도면 손만 좀 보면 되겠다" 싶었다.

그 안일함이 나중에 꽤 아팠다.

## "그럴듯한 숫자"의 정체

제출 직전에 근거를 정리하다가, 초안에 박혀 있던 정량 수치 몇 개를 원문에서 확인할 수 없었다. 어떤 건 출처가 아예 없었고, 어떤 건 원문에는 있는데 숫자가 미묘하게 달랐다. AI가 거짓말을 한 건 아니다. 학습 데이터에서 "이 자리에 어울릴 법한 숫자"를 골라 넣었을 뿐이다.

문제는 내가 그걸 "인용"으로 받아들였다는 것이다.

초안에 `모델 정확도 92%` 같은 문장이 있다고 치자. 이게 어디서 왔는지 나는 세 가지 중 하나로 나눠 봐야 했다. 논문에서 인용된 값인가. 내부 실험 결과인가. 아니면 그냥 모델이 자리를 채우려고 만든 숫자인가. 셋을 구분하지 않은 채로 제출하면, 심사에서 "이 수치 출처가 어디인가요"라는 질문 한 방에 무너진다.

## 초안 받기 전에 하는 일

지금은 순서를 바꿨다. AI에게 초안부터 시키지 않는다. **근거 맵을 먼저 만들고 그다음에 초안을 시킨다.**

맵은 대충 이렇게 생겼다.

```markdown
| 항목 | 근거 위치 | 검증된 내용 | 작성 제안 | 회사확인 필요 |
|------|-----------|-------------|-----------|--------------|
| 모델 성능 지표 | 관련 논문 Table 3 | QWK 0.81 | "QWK 0.81 (해당 논문 기준)" | 내부 재현 결과 첨부 |
| 시장 규모 | 공공기관 발간 보고서 | 세부 규모 확인됨 | 보고서 인용 | - |
| 비용 절감 효과 | - | 미확인 | AI 초안 수치 그대로 쓰지 말 것 | 파일럿 데이터 확보 후 작성 |
```

> QWK (Quadratic Weighted Kappa): 자동채점 모델이 사람 채점자와 얼마나 일치하는지 재는 지표. 1에 가까울수록 사람 채점과 붙는다.

이 표를 만드는 데 시간이 좀 걸리지만, 이걸 안 만들면 나중에 두 배로 걸린다. 그리고 AI에게 항목별 초안을 요청할 때 "이 근거를 바탕으로 이 항목을 써 달라"고 넘길 수 있게 되니, 애초에 헛소리를 할 여지가 줄어든다.

## 공개 출처와 내부 증빙을 섞지 마라

맵에서 가장 중요한 구분은 이거였다.

- **공개 출처 기반 주장** — 링크, 접근일, DOI 하나로 끝난다
- **내부 증빙 기반 주장** — 실험 로그, 계약서, 파일럿 결과가 별도 첨부로 따라와야 한다

AI 초안은 이 둘을 자연스럽게 섞어 쓴다. 심지어 하나의 문장 안에서도 섞는다. 분리해 두지 않으면 마감 직전에 "어? 이건 무슨 근거로 쓴 거지?" 하는 항목이 우수수 나온다. 공수가 완전히 다른 두 종류를 같은 걸로 취급하고 있었던 셈이다.

버킷을 나눠 두면 각 항목이 어떤 준비를 요구하는지 한눈에 보인다. 공개 출처 쪽은 확인만 하면 되지만, 내부 증빙 쪽은 사람에게 물어보고 자료를 받아야 한다. 이 리드타임을 놓치면 마감이 무너진다.

## HWP 레퍼런스는 텍스트로 먹인다

공공 도메인 사업계획서 작업에는 `.hwp` 레퍼런스가 자주 나온다. AI가 직접 못 읽으니 텍스트로 바꿔서 먹인다.

```bash
hwp5txt 레퍼런스문서.hwp > 레퍼런스문서.txt

# 표 구조를 살려야 할 때
hwp5html 레퍼런스문서.hwp > 레퍼런스문서.html
```

`hwp5txt`, `hwp5html`은 `python-hwp5` 패키지에 딸린 CLI다. 표가 중요한 문서는 HTML로 뽑아서 넘겨야 셀 단위 수치가 살아 남는다. AI가 "비슷한 숫자"를 자체 생성하는 여지를 물리적으로 줄이는 방법이다. 원문을 옆에 붙여 두면 모델이 딴 데서 숫자를 끌어올 이유가 없어진다.

## 아직 정리 못 한 것

내가 이걸 프로세스라고 부르긴 하지만, 사실 반쪽짜리다. 근거 맵을 만드는 것 자체를 AI에게 시켜도 되지 않을까 하는 유혹이 있는데, 그러면 맵의 근거를 다시 검증해야 하니 원래 문제로 돌아온다. 아직은 맵의 첫 열을 손으로 채우는 게 제일 안전하다고 본다.

그리고 "이 숫자는 AI가 생성한 것 같다"를 사후에 잡아내는 자동 검증기 같은 건 아직 못 만들었다. 지금은 눈으로 훑고, 의심스러운 자리는 원문에서 grep 해 보는 수밖에 없다. 다음에 시간이 나면 그쪽을 좀 파 볼 생각이다.
