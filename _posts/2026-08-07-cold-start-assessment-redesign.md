기존 질문지를 열어놓고 한참을 봤다. "연차가 몇 년이에요?", "직급은요?", "학습 방식은 강의파인가요 실습파인가요?", "언제까지 완료할 예정인가요?". 진단이라기보다 입사지원서에 가까웠다.

문제는 이 답들이 추천 결과를 실제로 얼마나 바꾸느냐였다. 연차가 5년이면 뭐가 달라지나. 학습 방식이 "실습파"면 어떤 콘텐츠가 위로 올라오나. 로직에 붙여봐도 대부분의 응답이 최종 순위에 미치는 영향이 미미했다. 즉, **응답을 받아놓고 실제로는 안 쓰고 있었다.** 온보딩에서 사용자의 4~5분을 뺏어놓고 그중 절반은 버려지고 있었다는 뜻이다.

## 뭘 근거로 추천이 되고 있는지부터 다시 봤다

일단 코드에서 사용자 상태를 어떻게 계산하고 있는지부터 확인했다. 콜드스타트를 이야기하려면, 콜드가 아닌 상태가 뭔지 먼저 정의돼 있어야 하니까.

```python
def _status(lifetime_xp: float, active_xp: float) -> str:
    if lifetime_xp <= 0:
        return 'new'
    ratio = active_xp / lifetime_xp if lifetime_xp else 0.0
    if active_xp >= 2 and ratio >= 0.6:
        return 'active'
    if lifetime_xp >= 10 and ratio < 0.5:
        return 'stale'
    return 'learning'
```

`lifetime_xp` 는 누적 학습 XP, `active_xp` 는 최근성 가중치 `recency_r` 이 붙은 XP다.

```python
def recency_r(learned_at: str | None, now: datetime) -> float:
    d = _days_since(learned_at, now)
    if d <= 182:
        return 1.0
    if d <= 365:
        return 0.7
    return 0.4
```

여기서 눈에 들어온 게 `'new'` 분기다. `lifetime_xp <= 0` 이면 그냥 new. 이 상태의 사용자는 strand·NCS별 레벨이 전부 0으로 붙는다. 즉 `level_of(xp) == 0`. 이 사람들에게 뭘 추천할지가 콜드스타트 문제 그 자체다.

레벨 계산은 로그 커브다.

```python
def level_of(xp: float) -> int:
    if xp <= 0:
        return 0
    return min(LEVEL_MAX, int(LEVEL_MAX * math.log(1 + xp / CURVE_L) / _LOG_DEN + 1e-9))
```

XP가 없으면 커브의 어느 지점에도 못 올라간다. 그러니 온보딩에서 뽑아야 할 정보는 결국 **"이 사용자를 어느 레벨 근처에 심을지"**, 그리고 **"어느 strand·NCS 축에 심을지"** 두 개다. 그 외의 응답은 사실상 장식이었다.

## 듀오링고를 다시 본 이유

이 지점에서 듀오링고 placement test가 떠올랐다. 몇 문항 안 되는데 사용자를 유닛 어딘가에 정확히 떨궈놓는다. 뭘 하는지 뜯어보면:

- **자기 보고를 안 받는다.** "당신은 중급인가요?"라고 안 묻는다. 중급 문제를 직접 풀게 한다.
- **응답에 따라 다음 문항이 바뀐다.** 첫 문제를 맞히면 다음은 어려워지고, 틀리면 쉬워진다. adaptive.
- **짧다.** 길면 이탈한다.

Item Response Theory 기반의 adaptive diagnostic 개념인데, 굳이 언어학습에만 쓸 이유가 없다. 우리가 하려는 것도 결국 같은 문제였다 — **몇 문항 안에 사용자를 좌표계 위 한 점으로 옮기기.**

기존 질문지가 하고 있던 건 반대였다. 좌표계를 만드는 대신 인구통계를 수집했다.

## 좌표계부터 정의하고 질문을 뽑는다

그래서 순서를 뒤집었다. "뭘 물어볼까"를 먼저 정하지 말고, **추천 로직이 어떤 축을 쓰는지**를 먼저 나열한 뒤, 그 축에 값을 실을 수 있는 질문만 남긴다.

로직 안에는 mode별로 축 가중치가 이미 정해져 있었다.

```python
MATRIX = {
    'job': {'level': 0.6, 'self': 0.2, 'trend': 0.2},
    'career': {'level': 0.4, 'self': 0.2, 'trend': 0.4},
    'company': {'level': 0.4, 'self': 0.4, 'trend': 0.2},
}
```

`level`, `self`, `trend` 세 축. 여기에 사용자의 학습 성향(character)이 델타로 붙는다.

```python
CHARACTER_AXIS_DELTA = {
    '실무 적용가': {
        'job': {'self': 0.04, 'trend': -0.04},
        'career': {'level': 0.03, 'trend': -0.03},
        'company': {'self': 0.03, 'trend': -0.03},
    },
    '트렌드 적응가': {
        'job': {'trend': 0.04, 'level': -0.04},
        'career': {'trend': 0.06, 'level': -0.04, 'self': -0.02},
        'company': {'trend': 0.05, 'level': -0.02, 'self': -0.03},
    },
    ...
}
```

또 career 단계별로 XP 보너스가 붙는다.

```python
CAREER_PROFILE_XP_BONUS = {'4~7년': 4.0, '8~10년': 8.0, '11년 이상': 14.0}

CAREER_STAGE = {'온보딩 ~1년': 0, '2~3년': 1, '4~7년': 2, '8~10년': 3, '11년 이상': 4}

AUDIENCE_STAGE_FIT = {0: 1.0, 1: 0.92, 2: 0.78, 3: 0.65}
```

이걸 다 늘어놓고 나니 온보딩에서 진짜로 필요한 값이 뭔지 보였다.

1. `career_stage` — XP 보너스와 audience stage fit에 직접 들어간다. 응답이 순위를 확실히 바꾼다.
2. `character` — 세 축 가중치를 재분배한다. 이것도 결과가 바뀐다.
3. strand/NCS 시드 — 콘텐츠 스타트 지점. 없으면 어떤 축에도 XP가 안 실린다.

그 외의 "학습 방식", "완료 목표 시점" 같은 답은 위 어느 자리에도 안 들어가고 있었다. 삭제.

## 무엇을 자기보고로 받고, 무엇을 안 받을지

여기서 듀오링고 원칙을 그대로 가져왔다. **자기보고로 받으면 편향이 큰 값은 행동으로 확인하고, 편향이 적은 값만 직접 묻는다.**

- `career_stage` 는 직접 받는다. 연차는 거짓말할 이유가 적고 확인도 어려우니 자기보고가 최선이다.
- `character` 는 직접 안 묻는다. "당신은 트렌드 적응가입니까?"는 답이 다 왜곡된다. 대신 4~5개 콘텐츠 카드를 A/B 비교로 보여주고 어느 쪽에 손이 가는지 본다. 콘텐츠 카드에 이미 태그가 붙어있으니 선택 패턴에서 character가 역산된다.
- strand/NCS 시드도 A/B 비교. 관심 있는 도메인 카드를 몇 장 골라내게 한 뒤, 거기 붙은 strand/NCS로 초기 XP를 살짝 심는다. 초기 XP는 `PREEVAL_LEVEL_XP = 0.7` 을 곱해 낮게 넣는다 — 아직 확정 아니니까.

비교 선택으로 몰아가는 이유는 하나 더 있다. 명시적 레이팅은 "3점"과 "4점"의 편차가 사람마다 다른데, 비교는 순서만 남기니 노이즈가 준다. 추천 논문에서 오래 확인된 것.

## 아직 남은 것

adaptive 부분은 아직 못 넣었다. 지금은 카드 4장을 병렬로 보여주는 수준이고, 첫 응답에 따라 다음 카드 세트를 바꾸는 로직은 다음 스프린트다. 문제는 카드 풀을 얼마나 세밀하게 태깅해둬야 다음 세트 선택이 의미있게 갈리느냐인데, 이건 아직 재보지 않았다. 카드 30장 정도로 4문항이 충분히 변별되는지, 아니면 100장까지 늘려야 하는지가 실측 이슈다.

그리고 `AUDIENCE_STAGE_FIT` 이 stage 차이 1당 0.08~0.14 정도로 떨어지게 잡혀 있는데, 이 계수가 온보딩 응답 정확도에 얼마나 민감한지도 아직 안 봤다. career_stage를 한 칸 잘못 받으면 추천이 얼마나 흔들리는지 — 여기가 다음에 열어볼 부분이다.
