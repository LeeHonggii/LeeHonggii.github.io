"추천이 제자리를 맴돈다"는 피드백을 받은 적이 있다. 유사도 점수는 멀쩡했다. 상위 10개를 뽑아 놓고 보면 대부분 이미 본 것과 같은 결의 콘텐츠였다. 관련도는 높은데, 사용자가 다음으로 갈 곳이 없었다.

이 글은 그 사이를 메우려고 붙인 두 개의 층 — 진행성 부스팅(progression boosting)과 RRF(Reciprocal Rank Fusion, 역순위 융합) — 을 어떻게 설계했는지에 대한 기록이다. 정답을 찾은 이야기가 아니라, 한 번 잘못 짰다가 뒤집은 이야기다.

## 유사도가 답하지 않는 질문

첫 파이프라인은 단순했다. 콘텐츠 간에 키워드 겹침, 직무 매핑, 학습 방향(stance) 일치율을 가중 합산해 `base_relevance` 하나를 뽑는다. 잘 나왔다. 코사인 유사도 대신 도메인 신호를 섞은 만큼, "무관한 것이 상위에 뜨는" 사고는 거의 없었다.

문제는 다른 데 있었다. `base_relevance` 는 정적이다. 사용자가 시리즈의 몇 번째 편을 봤는지, 같은 난이도에서 몇 번을 맴돌았는지, 어제 뭘 완료했는지를 하나도 반영하지 않는다. 관련도만으로 정렬하니 관련도가 높은 것들이 계속 상위에 남았다. 학습 서비스에서 이건 실패다. "비슷한 걸 잘 찾는 시스템"과 "다음에 볼 것을 잘 고르는 시스템"은 다른 문제였다.

그래서 진행성 신호를 얹기로 했다.

## 처음엔 덧셈으로 짰다 — 그리고 곧 뒤집었다

부스팅을 처음 붙일 때는 자연스럽게 이렇게 썼다.

```
final_score = base_relevance + boost_sum
```

시리즈 다음 편이면 +0.2, 난이도 한 단계 위면 +0.15, 이런 식이었다. 하루 만에 문제가 드러났다. `base_relevance` 가 0.1밖에 안 되는, 그러니까 "이 사용자와 별로 관련 없는" 콘텐츠가 "다음 시리즈편"이라는 이유만으로 상위 5위 안에 들어왔다. 관련이 없는데 순서만 맞다는 이유로 추천되는 상황이다.

덧셈은 두 축을 독립적으로 취급한다. 관련도가 없어도 진행성만 강하면 뜬다. 우리가 원한 건 그 반대였다 — **진행성은 관련도 위에서만 의미가 있다.** 그러면 곱셈이어야 했다.

```
final_score = base_relevance * (1 + boost_sum)
```

`base_relevance` 가 낮으면 아무리 부스팅을 받아도 절대값이 안 뜬다. 관련도가 게이트 역할을 하고, 그 게이트를 넘은 것들 사이에서 진행성이 순위를 흔든다. 원했던 우선순위가 그대로 표현됐다.

부스팅 조건은 네 가지로 정리했는데, 이 목록 자체보다 **왜 이것들이어야 했는가** 가 중요하다.

- 시리즈의 바로 다음 편: 명시적 순서가 있는 콘텐츠에서 가장 강한 신호
- 난이도 한 단계 상승: "한 단계"에 방점. 두 단계 위는 부스팅 대상 아님
- 같은 분야 내 심화: 직무 범주는 유지, 주제 깊이만 증가
- 직급 한 단계 상향: 시야를 조금만 넓혀주는 방향

공통적으로 "한 칸 옆/위". 두 칸을 뛰지 않는다. 학습에서 점프는 이탈을 만든다는 게 로그에서 보였고, 그래서 부스팅은 의도적으로 짧은 거리에만 걸었다.

한 가지 더, 부스팅 값에 하한선을 뒀다.

```
BOOST_BASE_FLOOR = 0.5
```

조건이 약하게 충족될 때 `boost_sum` 이 0에 가까워지면 곱셈 효과가 소멸한다. 그러면 부스팅을 넣은 의미가 없어져서, 조건이 하나라도 걸리면 최소 0.5를 유지하도록 바닥을 깔았다. 이 숫자는 이론적 근거보다는 여러 값을 돌려보고 결과가 가장 덜 극단적으로 나온 지점을 잡았다. 실측이라기보다 감각에 가까운 튜닝이라, 이후 사용 로그가 쌓이면 다시 봐야 한다.

## 관점이 다른 점수는 합칠 수 없었다

그다음 문제는 다른 층에서 왔다. 추천에는 관점이 여럿이었다 — 직무 적합도, 관심 키워드, 학습 선호 패턴. 각 관점이 독립적으로 점수를 뱉었는데, 이 점수들의 스케일이 제각각이었다.

직무 점수는 0에서 1 사이를 넓게 채웠다. 상위와 하위 격차가 컸다. 반면 선호 패턴 점수는 0.1과 0.3 사이에 몰려 있었다. 셋을 그냥 더하면 결과는 사실상 직무 점수가 지배한다. 다른 관점은 소수점 자리 노이즈처럼 취급된다.

정규화(min-max, z-score)를 시도해봤지만 세 관점의 분포 자체가 달라서, 정규화 후에도 "어떤 콘텐츠가 어느 관점에서 잘 나왔는지"의 정보가 뭉개졌다. 스케일을 억지로 맞추는 대신, **점수 자체를 버리고 순위만 쓰기로** 했다. Reciprocal Rank Fusion이다.

```
RRF_score(d) = Σ_i  1 / (k + rank_i(d)),   k = 60
```

각 관점에서 콘텐츠를 정렬해 순위를 매기고, 순위의 역수를 합산한다. `k = 60` 은 원 논문의 기본값으로, 최상위 몇 개의 격차를 완만하게 눌러주는 역할을 한다. 1등과 2등의 점수 차이가 지나치게 벌어지지 않게 해서, 여러 관점에서 고르게 잘 나온 콘텐츠가 특정 관점 1위만 있는 콘텐츠를 이길 여지를 남긴다.

숫자로 감을 잡으려고 한 예를 계산해봤다. 어떤 콘텐츠가 직무 관점 3위, 관심 관점 7위, 선호 관점 2위라면

```
RRF = 1/(60+3) + 1/(60+7) + 1/(60+2)
    ≈ 0.01587 + 0.01493 + 0.01613
    ≈ 0.04693
```

각 항이 비슷한 크기로 기여하는 게 중요하다. 어느 관점에서든 상위권이면 대략 0.015 근처를 얹고, 하위권으로 갈수록 완만하게 줄어든다. 스케일이 안 맞아서 한 관점이 결과를 삼키는 문제가 사라졌다.

RRF의 한계도 인정해야 한다. 순위만 쓰는 순간 "얼마나 크게 이겼는지"가 사라진다. 직무 관점에서 압도적 1위인 콘텐츠와 간발의 차로 1위인 콘텐츠가 같은 값을 받는다. 이게 문제가 되는 케이스가 있을 것 같은데, 아직 그런 사례를 로그에서 잡아내진 못했다. 잡히면 관점별 가중치를 RRF에 얹는 방향(weighted RRF)을 볼 생각이다.

## 남은 것

두 층을 얹은 뒤 추천 결과의 다양성은 눈에 띄게 늘었다. 다만 이건 인상평이지 지표가 아니다. 진행성 부스팅이 실제로 "다음 단계 완료율"을 올렸는지는 아직 A/B로 재보지 않았다. `BOOST_BASE_FLOOR = 0.5` 도 감각 튜닝이라 다시 볼 대상이다. RRF의 `k=60` 은 건드릴 이유를 아직 못 찾았지만, 관점을 하나 더 추가하면 재검토해야 할 수 있다.

지금 애매하게 남아 있는 판단이 하나 더 있다. 부스팅 조건 네 개에 각각 다른 가중치를 줘야 하는가, 아니면 지금처럼 동일 가중이 맞는가. "시리즈 다음 편"과 "직급 한 단계 상향"이 같은 무게라는 건 직관적으로는 어색한데, 다르게 줄 근거를 아직 갖고 있지 않다. 로그가 더 쌓이면 답이 나올 문제다.
