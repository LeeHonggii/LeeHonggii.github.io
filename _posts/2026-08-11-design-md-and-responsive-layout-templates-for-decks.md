AI에게 슬라이드를 그리게 하면 이상한 지점에서 무너진다. 색은 맞는데 구도가 어긋나거나, 격자는 예쁜데 폰트가 회사 가이드와 다르거나. 처음엔 프롬프트를 손봤다. 소용없었다. 문제는 프롬프트가 아니라 **내가 모델에 넘기는 컨텍스트가 두 개의 다른 이야기를 한 파일에 섞어놓은 것**이었다.

## 한 파일에 다 넣었을 때

브랜드별 CSS를 한 파일로 관리하던 시절이 있었다. `<brand>.css` 하나에 색상 변수, 폰트 스택, `--spacing-*`, 슬라이드 레이아웃 클래스, 반응형 미디어쿼리까지 다 들어있었다. 브랜드가 늘 때마다 파일을 복사하고 색만 바꿔서 새로 만들었다. 레이아웃은 어차피 다 비슷하니까.

그러다 레이아웃 하나를 고치면 브랜드 수만큼 같은 수정을 반복해야 했다. 이건 사람이 겪는 문제고, 그건 참을 만했다.

참을 수 없었던 건 이 파일을 AI에게 컨텍스트로 넘겼을 때 나오는 결과였다. "bento grid로 만들어줘"라고 하면 모델은 격자를 그리긴 하는데, 색을 자기 마음대로 골랐다. 어떤 슬라이드는 브랜드 팔레트를 벗어난 warm accent를 채워넣기도 했다. 팔레트에 없는 색이 어디서 나왔는지 추적해보니, 파일 아래쪽에 있던 예전 예제 코드 조각에서 참조되고 있었다. 모델은 그걸 팔레트의 일부로 오해했다.

관심사가 섞이면 추론도 섞인다. 이걸 그때 배웠다.

## 디렉터리로 갈랐다

해결은 파일을 나누는 것이 아니라 **폴더를 나누는 것**이었다. 물리적으로 다른 위치에 있어야 모델이 "지금 참조해야 하는 건 이 폴더 하나"라고 명확하게 판단한다.

```
00_System/
  design_styles/
    <brand>/
      DESIGN.md      # 색·폰트·간격·컴포넌트 규칙
  deck_layouts/
    <layout>/
      LAYOUT.md      # HTML 구조·Marp 클래스 패턴
```

`DESIGN.md`는 브랜드 정체성이다. Hex 값, 폰트 패밀리, 로고 사용 규칙. `LAYOUT.md`는 슬라이드 한 장의 시각 구조다. bento grid, code-focus, timeline, comparison matrix, device mockup 같은 패턴이 여기 산다.

Marp에서는 슬라이드별로 이렇게 선언한다.

```html
<!-- _class: layout-bento-grid -->
```

CLI에서는 전체 지정과 슬라이드별 지정을 분리했다.

```bash
make_deck.py input.md --layout bento-grid

make_deck.py input.md \
  --per-slide-layouts '{"2":"code-focus","3":"comparison-matrix"}'
```

두 인자가 겹치면 슬라이드별 지정이 우선한다. 이건 순전히 실사용에서 정해진 규칙이다 — 전체 톤은 하나로 가되, 특정 장만 다르게 강조하고 싶은 경우가 훨씬 많았다.

## PPTX와 HTML을 억지로 붙이지 않기

한동안 PPTX와 HTML 덱을 같은 레이아웃 시스템으로 다루려고 했다. 결국 포기했다.

PPTX는 픽셀 좌표를 잡는 매체다. `layout-bento-grid`를 PPTX에 그대로 옮기면, HTML에서 2×3으로 유연하게 감기던 것이 슬라이드 크기에 딱 맞춰 굳어버린다. HTML은 뷰포트에 반응해야 하고, PPTX는 반응할 필요가 없다. 같은 이름의 같은 개념이라고 우기면 둘 다 어색해진다.

지금은 PPTX 쪽은 테마 선택 1~2개로 좁혔다. HTML 쪽만 슬라이드별 레이아웃을 열어뒀다. 이 판단이 옳았는지는 아직 더 써봐야 안다 — 실제로 PPTX 사용자가 슬라이드별 레이아웃을 요구한 적은 아직 없었지만, 그건 못 하게 막아둬서일 수도 있다.

## 카드가 없으면 AI가 못 고른다

레이아웃을 나눈 것만으로는 부족했다. AI에게 "적절한 레이아웃을 골라라"라고 시켰을 때, 파일 이름과 CSS만 던져주면 모델이 왜 그 이름인지를 추론해야 했다. 이름이 `bento-grid`인 건 힌트가 되지만, `code-focus`가 어떤 상황에 어울리는지는 이름만으로 애매하다.

그래서 `LAYOUT.md` 상단에 짧은 카드를 붙였다.

```markdown
# bento-grid

용도: 여러 정보를 동등한 비중으로 나열할 때
구조: 2×2 또는 2×3 격자, 각 셀에 아이콘·수치·짧은 설명
어울리는 콘텐츠: 기능 비교, 지표 요약, 팀 소개
안 맞는 콘텐츠: 시간 순서가 있는 이야기, 코드 인용
```

"안 맞는 콘텐츠"를 넣은 게 컸다. 긍정 예시만 주면 모델이 뭐든지 bento로 만들려 든다. 부정 예시가 있어야 다른 레이아웃으로 넘어간다.

## 아직 못 푼 것

두 가지가 애매하게 남아있다.

하나는 **레이아웃끼리 섞일 때**다. 어떤 슬라이드는 "timeline인데 셀 안이 bento처럼 격자"인 경우가 있다. 지금은 이걸 새 레이아웃 파일로 만들지, 아니면 timeline 안에서 조합 규칙을 열지 고민 중이다. 파일이 늘어나는 건 관리 비용이 오르고, 조합을 여는 건 카드 명세가 다시 흐려진다.

다른 하나는 **DESIGN.md의 accent 토큰**이다. 브랜드에 강조색이 두세 개 있을 때, 그중 하나를 예시로 넣어두면 모델이 그걸 주 팔레트처럼 다룬다. 예시 없이 명세만 두면 사용을 못 한다. 지금은 화이트리스트로 Hex를 못박아두고 있는데, 이게 옳은 지점인지는 다음 브랜드를 추가해봐야 확실해질 것 같다.
