## 프롬프트만으로는 안 됐다

발표자료를 AI에게 맡기면 늘 같은 지점에서 무너졌다. 요약된다. 내가 굳이 두 문단으로 나눠 쓴 이유가 있는데 한 줄로 붙여버린다. 표의 셀 하나를 통째로 날리기도 한다. 그때마다 원본 md를 다시 열어 대조하는 게 일이었다.

처음엔 프롬프트로 눌러보려 했다. "요약하지 마라", "원문 그대로 옮겨라", "문장을 절대 자르지 마라". 그럴듯하게 작동하는 것 같다가도 긴 단락을 만나면 슬그머니 줄인다. 모델이 "슬라이드 한 장에 이만큼 못 넣는다"라고 판단하는 순간, 명시적 지시보다 그 판단이 이긴다.

그래서 방향을 뒤집었다. 모델한테 내용을 맡기지 않는다. 내용은 파이썬이 자른다. 모델은 자르는 위치를 도와주고, 어느 레이아웃이 어울리는지만 골라준다.

## 규칙 하나: 삭제·요약 금지, 분할만 한다

작동 원리는 이 문장 하나로 요약된다.

- H2 섹션 1개 → 짧으면 슬라이드 1장 (1:1)
- H2 섹션 1개 → 길면 슬라이드 여러 장 (1:N)
- 어떤 경우에도 문장은 통째로 이동한다. 문장 중간에서 자르지 않는다

내가 md에 쓴 모든 문장은 결과 슬라이드 어딘가에 그대로 들어가 있어야 한다. 이걸 도구의 계약처럼 정해두고, 결과물을 볼 때마다 검증했다. 초기엔 검증에 실패하는 케이스가 계속 나왔고, 그때마다 분할 로직 쪽 문제였지 프롬프트 문제가 아니었다. 이 경험이 "모델 바깥으로 뺀다"는 결정을 강화했다.

## DESIGN.md — 브랜드를 파일로 관리한다

두 번째로 무너지기 쉬운 지점은 "이번엔 이 회사 톤으로", "다음엔 저 톤으로" 같은 요청이었다. 처음에는 파이썬에 팔레트를 하드코딩했는데, 브랜드 하나 추가할 때마다 코드를 만졌다. 이건 유지가 안 될 구조였다.

대신 볼트 안에 컬렉션을 뒀다.

```
00_System/design_styles/
├── claude/DESIGN.md
├── minimal/DESIGN.md
└── corporate/DESIGN.md
```

각 `DESIGN.md`는 팔레트, 폰트, 제목·본문 크기, 강조 컴포넌트를 md 표와 코드 블록으로 정의한다. 새 브랜드는 폴더 하나 만들고 파일 하나 채우면 끝이다. 두 번째 브랜드를 추가할 때 파이썬을 열지 않았다는 사실 하나로 이 구조가 살아남을 수 있겠다는 감이 왔다.

레이아웃도 같은 방식으로 뺐다.

```
00_System/deck_layouts/
├── hero/LAYOUT.md
├── bento-grid/LAYOUT.md
└── two-column/LAYOUT.md
```

슬라이드별로 강제 지정도 된다.

```bash
--per-slide-layouts '{"0":"hero","1":"bento-grid"}'
```

0번은 hero, 1번은 bento-grid. 나머지는 내용 길이·성격에 따라 자동으로 붙인다.

## 한 번 실행, 두 포맷

발표는 대면일 때도 있고 링크로 공유할 때도 있다. PPTX 하나만 뽑아두면 브라우저에서 열어볼 때 늘 어색했다.

```bash
python3 make_deck.py \
  --md input.md \
  --style claude \
  --mode both \
  --vault /Users/me/obsidian-vault
```

`--mode both`를 주면 두 결과물이 같은 소스에서 나온다.

```
output/decks/pptx/<slug>.pptx
output/decks/web/<slug>/index.html
```

PPTX는 python-pptx로, HTML은 별도 템플릿으로 만든다. 여기서 처음엔 "레이아웃 하나로 두 포맷 모두 커버하자"라고 시작했는데, 몇 번 만들어보고 접었다. bento-grid를 PPTX에서 잡을 때 쓰는 좌표 로직과 HTML에서 화면 폭에 따라 단일 컬럼으로 접는 로직은 애초에 다른 문제다. 억지로 통합하려다 두 쪽 다 어색해졌다. 그래서 레이아웃 이름·의도는 공유하되 구현은 분리했다.

## 아직 안 된 것

Obsidian 커맨드 팔레트에서 바로 부르는 걸 하고 싶은데 아직 못 붙였다. 지금은 터미널로 실행한다. 실행 옵션이 많다 보니 커맨드 하나로 정리하려면 인자를 어떻게 노출할지가 애매하게 남아 있다.

그리고 "AI가 잘라도 되는 부분"과 "사람이 지켜야 하는 부분"의 경계선은 지금도 계속 흔들린다. 코드 블록은 절대 자르지 않는다는 규칙은 확실한데, 인용 블록 안의 긴 단락은 자를지 말지 매번 고민한다. 재보지 않은 감각이라 아직 규칙으로 못 굳혔다.
