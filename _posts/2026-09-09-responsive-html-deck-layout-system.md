Marp로 마크다운 하나에서 PPTX와 HTML을 동시에 뽑는 도구를 만들다가 한 가지 문제에 걸렸다. PPTX 쪽은 비교적 단순했다. 브랜드 색상 팔레트와 폰트를 고르면 나머지는 Marp 테마가 처리한다. 그런데 HTML 모드를 만들면서 같은 방식으로 접근하려다 멈췄다.

HTML 발표자료는 PPT가 아니다. 브라우저에서 열리고, 화면 비율이 다를 수 있고, 스크롤도 가능하다. 그런데 나는 "어떤 브랜드 색상 쓸까요?" 같은 질문을 HTML에도 똑같이 던지고 있었다. 색상 선택이 나쁜 게 아니라, 그게 HTML에서 가장 중요한 선택이 아니었다.

HTML 슬라이드에서 실제로 시각적 차이를 만드는 건 **레이아웃 패턴**이다. 제목 하나에 텍스트 블록 하나인 슬라이드와, 왼쪽에 텍스트 오른쪽에 이미지가 나란히 있는 슬라이드는 같은 색상 테마를 써도 완전히 다르게 보인다. Bento grid로 정보를 쪼개 배치하면 같은 내용도 훨씬 밀도 있어 보인다.

그래서 UI를 바꿨다. PPTX 모드는 "브랜드 선택", HTML 모드는 "레이아웃 패턴 선택"으로 분리했다.

## 레이아웃 템플릿을 파일로 관리하기

각 레이아웃은 독립 디렉터리로 관리한다. 구조는 대략 이렇다:

```
00_System/deck_layouts/
├── hero/
│   └── LAYOUT.md
├── split/
│   └── LAYOUT.md
├── code-focus/
│   └── LAYOUT.md
├── bento-grid/
│   └── LAYOUT.md
└── magazine-editorial/
    └── LAYOUT.md
```

`LAYOUT.md`에는 이 레이아웃이 언제 적합한지, CSS가 어떻게 생겼는지, 슬라이드에서 어떻게 호출하는지가 적혀 있다. 레이아웃을 추가하려면 디렉터리를 하나 만들고 `LAYOUT.md`를 채우면 된다. 파이썬 코드를 건드리지 않아도 된다.

레이아웃이 파일 시스템에 있으면 AI가 생성 단계에서 읽어갈 수 있다는 장점도 있다. 마크다운 원고를 슬라이드로 분할할 때, 각 섹션에 어떤 레이아웃이 어울리는지 LAYOUT.md를 참고해서 판단한다.

## 슬라이드마다 다른 레이아웃

Marp는 슬라이드별로 클래스를 지정하는 문법을 지원한다.

```markdown
<!-- _class: layout-bento-grid -->

## 이번 분기 주요 지표

- 항목 A: ...
- 항목 B: ...
- 항목 C: ...
```

주석 한 줄로 해당 슬라이드만 bento grid로 바꿀 수 있다. 전체 덱 레이아웃과 별개로 특정 페이지만 다르게 구성하고 싶을 때 쓴다.

CLI에서는 이렇게:

```bash
python make_deck.py input.md \
  --format html \
  --per-slide-layouts '{"2":"code-focus","3":"comparison-matrix"}'
```

2번 슬라이드는 코드 중심 레이아웃, 3번은 두 컬럼 비교 레이아웃으로 override한다. JSON으로 받기 때문에 0개든 10개든 일관하게 처리된다.

## 실제로 써보니

hero 레이아웃은 표지 슬라이드에 잘 맞는다. 큰 제목 하나, 짧은 부제목. split은 텍스트와 이미지를 나란히 놓을 때. code-focus는 코드 블록이 메인이고 설명이 사이드에 붙는 구조라 기술 발표에서 자주 쓰게 됐다.

magazine-editorial은 처음에 "이게 발표자료에서 어디 쓰지?" 싶었는데, 사례 소개 슬라이드에서 의외로 효과가 있었다. 큰 인용구 하나와 작은 보조 텍스트 블록을 비대칭으로 배치하면 내용보다 분위기가 먼저 전달된다.

bento-grid는 아직 좀 어렵다. 칸 수와 비율을 어떻게 지정하느냐에 따라 결과가 많이 달라지는데, 지금은 2×2 고정이다. 3칸짜리나 비대칭 배치는 아직 지원하지 않는다.

레이아웃 자동 추천도 만들어두긴 했다. 슬라이드 원고에 코드 블록이 있으면 code-focus, 항목이 6개 이상이면 bento-grid, 이미지 경로가 있으면 split을 권장하는 식이다. 그런데 추천이 맞는 경우보다 틀리는 경우가 더 많아서 아직 기본값으로 켜두지 않고 있다.
