"기존 사전 설문이 너무 추상적이다. 다시 만들자."

이 한 마디를 들었을 때 손이 먼저 움직였다. GPT 창을 열고 프롬프트를 던지면 그럴싸한 문항 스무 개쯤은 금방 나온다. 그런데 타이핑 중간에 멈췄다.

*그럴싸한 것*과 *효과가 검증된 것*은 다르다.

좋은 진단 설문 뒤에는 심리측정학과 교육공학이 수십 년 쌓아온 설계 원칙이 있다. 그걸 건너뛰고 LLM 직감으로 문항을 짜면 며칠 뒤에 다시 뜯어고치게 된다는 걸, 그동안 몇 번 겪어봤다. 그래서 이번엔 순서를 바꿨다. **질문지를 쓰기 전에, 검증된 사례와 연구를 먼저 모으는 리서치 단계를 따로 두기로 했다.** 도구는 NotebookLM을 골랐다.

## 왜 NotebookLM인가

NotebookLM은 구글이 만든 AI 리서치 노트 도구다. PDF·웹 페이지·유튜브 링크 여러 개를 한 노트북에 묶어두고, **그 소스 안에서만** 근거를 찾아 답한다. 이 "소스 밖은 안 본다"는 성질이 이번 목적에 정확히 맞았다. 할루시네이션(hallucination, AI가 사실이 아닌 것을 사실처럼 꾸며내는 현상) 리스크가 큰 리서치 단계에서, 근거가 원문 어디에 있는지 짚어주는 도구가 필요했다.

CLI 로그인부터 확인했다.

```bash
notebooklm login          # 구글 계정 인증
notebooklm list           # 기존 노트북 목록 확인
```

## 세 축으로 쪼갠 이유

새 노트북을 만들면서 처음 한 일은 리서치 주제를 나누는 것이었다. 한 덩어리로 넣으면 개념이 뒤섞인다는 감이 왔다.

| 축 | 리서치 키워드 |
|---|---|
| 1 | Duolingo placement test 설계 원칙 |
| 2 | Cold-start preference elicitation (콜드스타트 선호 추출) |
| 3 | Adaptive diagnostic assessment (적응형 진단 평가) |

셋은 겉보기엔 다 "초기 사용자에게 뭘 물어볼까"인데, 목적이 다르다. Duolingo식은 초기 레벨 분류. 콜드스타트는 추천 시스템의 초기 선호 파악. adaptive diagnostic은 능력 추정을 반복적으로 좁혀가는 방식. 이걸 한 노트북에서 뭉뚱그리면 나중에 답변이 나올 때 "이건 어느 맥락의 얘기지?"가 계속 걸린다.

## Deep research를 먼저, 설계는 그다음

각 축에 deep research를 걸었다.

```
Deep research: Duolingo placement test
Deep research: cold-start preference elicitation
Deep research: adaptive diagnostic assessment
```

"빠른 임시 리서치"로 대충 훑고 바로 문항 초안을 시작할 수도 있었다. 안 그러기로 한 건 두 번 데였기 때문이다. 반쯤 읽은 상태에서 설계를 시작하면 이미 읽은 소스에 편향된다. 아직 안 연 논문이 정작 핵심 인사이트를 담고 있을 때가 있다. 그리고 리서치와 설계를 동시에 굴리면 컨텍스트가 왔다갔다 하면서 둘 다 얕아진다.

기다리는 시간이 아까워 보이지만, 이 순서를 지키는 게 결과적으로 빨랐다.

## 각 축에서 건진 것

**Duolingo placement test.** 초기 문항을 의도적으로 쉽게 시작해서 연속 정답이 나오면 레벨을 빠르게 올리는 이진 탐색(binary search) 패턴이 뼈대였다. 문항 수 자체는 많이 필요하지 않았다. 오히려 초반에 이탈하지 않게 만드는 UX 흐름이 정확도만큼 중요했다는 게 반복해서 나왔다. "짧게, 그러나 점프하듯 난이도를 조정."

**Cold-start preference elicitation.** 추천 시스템 논문들이 공통으로 쓰는 방식은 크게 두 갈래였다. 샘플 아이템을 직접 골라보게 하는 방식, 그리고 속성 기반으로 선호를 물어보는 방식. 사전 설문에 옮겨보면 "어떤 유형의 콘텐츠를 좋아하세요?"라고 묻는 것보다 "이 세 가지 샘플 중 가장 끌리는 것은?"이 훨씬 정보가 많다. 사용자가 스스로도 모르는 선호는 텍스트 응답으로 안 나온다.

**Adaptive diagnostic.** 여기서는 IRT(Item Response Theory, 문항반응이론) 기반 CAT(Computerized Adaptive Testing, 컴퓨터 적응형 시험)이 사실상 표준이었다. 완전 구현은 문항 파라미터 캘리브레이션까지 필요해서 무겁다. 다만 "이전 응답에 따라 다음 문항 난이도를 조정"이라는 원칙만 떼어 오면, 룰 기반 근사로도 초기 버전은 만들 수 있겠다는 감이 왔다.

## 남은 것

리서치를 끝내고 나니 재밌는 지점이 있었다. 세 축이 서로 배타적이지 않았다. Duolingo식 이진 탐색은 adaptive diagnostic의 아주 단순화된 형태고, 콜드스타트의 샘플 선택 방식은 초기 문항 몇 개를 "예열용"으로 배치하는 아이디어로 붙일 수 있다. 이걸 어느 비율로 섞을지는 아직 못 정했다.

문항 초안은 이제부터 쓴다. 오늘은 여기서 멈춘다. 설계 하루보다 리서치 하루가 먼저인 순서 — 이번엔 이게 맞았다고 느꼈지만, 다음 번에도 같은 순서일지는 그때 가서 다시 본다.
