발표자료를 만드는 방식이 오래됐다고 느낀 건 꽤 전부터였다. 글을 써서 공유하면 Markdown인데, 같은 내용을 발표로 만들면 PowerPoint로 처음부터 다시 시작했다. 두 가지 결과물이 별개의 파일로 존재하면, 내용이 바뀔 때마다 두 군데를 고친다. 한쪽은 항상 뒤처진다.

그래서 **Markdown을 단일 소스로 두고, PPTX와 HTML 덱을 동시에 뽑아내는 흐름**을 만들기로 했다.

---

## Marp가 이미 해결해 놓은 것

[Marp](https://marp.app/)는 Markdown을 슬라이드로 변환하는 도구다. 핵심은 CLI 두 줄이다.

```bash
marp deck.md --pptx -o deck.pptx
marp deck.md --html -o deck.html
```

같은 파일에서 편집 가능한 PPTX와 브라우저에서 바로 열리는 HTML이 나온다. 여기까지는 공식 문서에 있는 내용이다.

문제는 실제로 써보면 기대와 다른 부분이 생긴다는 것이다.

---

## 먼저 부딪힌 것: 내용 유실

긴 Markdown 문서를 발표자료로 만들 때, 가장 흔한 실수는 "요약하면 슬라이드가 된다"는 가정이다. 요약하면 원문에 있던 맥락이 빠진다. 발표자는 알고 있지만, 슬라이드만 보는 사람은 모른다.

내가 선택한 방향은 요약보다 **구조 분할** 이었다. 원문의 논리 흐름을 유지하면서, 슬라이드 경계를 어디서 끊을지를 결정하는 것. 그러려면 입력 Markdown이 어느 정도의 분량인지 먼저 파악해야 한다.

토큰 수를 먼저 세고, 슬라이드 한 장당 허용 토큰 예산을 정해, 분할 계획을 잡는 방식으로 접근했다. "이 내용이 슬라이드에 들어가는가?" 가 아니라, "원문 어디까지가 이 슬라이드의 범위인가?" 를 묻는 것이다.

## 디자인과 레이아웃을 분리한 이유

Marp는 CSS 테마를 지원한다. 색상, 폰트, 여백을 CSS로 정의하면 PPTX와 HTML 양쪽에 적용된다.

그런데 실제로는 두 가지 관심사가 섞여 있다.

- **디자인 시스템**: 브랜드 색상, 타이포그래피, 슬라이드 비율
- **레이아웃 템플릿**: 제목 슬라이드, 2단 구성, 코드 슬라이드, 마무리 슬라이드 같은 구조

이 둘을 하나의 CSS 파일에 넣으면, 디자인을 바꿀 때 레이아웃이 깨지고, 레이아웃을 추가할 때 디자인 값을 건드려야 한다.

그래서 `--design` 과 `--layout` 을 별도 인자로 받도록 했다.

```bash
python make_deck.py input.md \
  --mode both \
  --design corporate \
  --layout two-column
```

`--design` 은 브랜드 스타일을 담은 CSS 슬러그, `--layout` 은 슬라이드 구조 템플릿이다. 둘을 조합하면, 같은 레이아웃을 다른 브랜드로, 같은 브랜드를 다른 구조로 쓸 수 있다.

---

## HTML 덱이 PPTX와 다른 점

HTML로 뽑으면 브라우저에서 키보드로 조작하는 풀스크린 덱이 된다. 여기서 문제가 하나 있다.

PPTX는 슬라이드 비율이 고정이다. 16:9면 16:9다. HTML은 뷰포트 크기에 따라 달라진다. 모바일에서 열면 레이아웃이 깨진다.

반응형 처리를 Marp CSS에서 하려면 `@media` 쿼리가 필요하다. 그런데 Marp의 슬라이드 렌더링 방식은 `transform: scale()` 기반이라, 미디어 쿼리만으로는 해결이 안 되는 경우가 있다. 현재는 데스크탑 기준 HTML만 보장하고, 모바일 대응은 아직 완전히 해결하지 않았다.

---

## 지금 남아 있는 것

PPTX에서 이미지 품질이 원본보다 낮게 나오는 케이스가 있다. Marp의 Chromium 기반 렌더링을 거치면서 생기는 문제인 것 같은데, DPI 설정을 바꾸는 방법이 공식적으로 지원되지 않는다. 우회 방법을 찾아봤지만 아직 깔끔하게 정리되지 않았다.

레이아웃 템플릿도 아직 두 가지밖에 없다. 실제로 쓰다 보면 "이 내용은 이 구조로 안 된다"는 경우가 나올 것이고, 그때마다 하나씩 추가하게 될 것 같다.
