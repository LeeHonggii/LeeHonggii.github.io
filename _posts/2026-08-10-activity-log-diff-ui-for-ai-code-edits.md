## 피드가 벽이 됐다

AI 코딩 에이전트를 붙여 놓고 며칠 지나니 활동 로그(activity log)가 스크롤로 감당이 안 됐다. 파일 열고, 읽고, 고치고, 다시 읽고. 이벤트 하나하나가 카드가 되어 세로로 늘어졌다. "이 에이전트가 방금 뭘 바꿨더라?"를 찾으려면 위로 한참을 거슬러 올라가야 했다.

문제를 하나로 뭉뚱그리면 "노이즈가 많다"였는데, 뜯어보니 층이 나뉘어 있었다.

- 같은 도구 호출이 **두 번** 찍힌다 (호출 전/후)
- 카드가 접혀 있으면 **뭘 바꿨는지 안 보인다** — 열어봐야 안다
- 열어보면 이번엔 **너무 다 보인다** — 300줄짜리 diff가 통째로

세 층이니까 세 번 나눠 다뤘다.

## 층 1 — 같은 호출을 두 번 그리지 마라

에이전트가 도구를 부르는 순간은 두 이벤트로 쪼개져 흐른다. 도구 호출 직전의 `PreToolUse`, 결과가 돌아온 뒤의 `PostToolUse`. 입력만 있고 결과가 없는 카드와, 결과만 있고 입력이 흐릿한 카드가 번갈아 쌓였다. 사람 눈에는 그냥 "같은 짓 두 번".

묶는 방법은 단순하다. 도구 이름과 입력 인자를 합쳐 해시를 뜨고, 그 지문(fingerprint)으로 대기 테이블에 물려 뒀다가 결과가 도착하면 꺼내 합친다.

```js
const fingerprint = md5(toolName + JSON.stringify(input));
// pre 이벤트: pendingMap[fingerprint] = card
// post 이벤트: pendingMap[fingerprint] 꺼내서 result 채움 → 렌더
```

키 자체는 별 게 없다. 핵심은 **키를 만들 재료를 뭐로 쓸지**였다. 처음엔 이벤트 시각을 섞었는데, 그러면 pre와 post의 타임스탬프가 달라져 지문이 안 맞았다. 시각을 뺐다. 그다음엔 도구 인자 안에 랜덤 ID가 섞여 있는 경우가 있었는데, 그건 pre/post 양쪽에 동일하게 실려 오는 거라 오히려 지문을 안정시켜 줬다. 그래서 인자를 통째로 JSON 직렬화해서 넣는 걸로 정착했다.

이 하나로 피드 길이가 눈에 띄게 줄었다. 정확히 몇 % 줄었는지는 재보지 않았다. 스크롤을 덜 돌리게 된 걸로 충분했다.

## 층 2 — 접힌 카드에서도 뭐가 바뀌었는지 보이게

카드를 묶고 나니 이번엔 다른 게 걸렸다. 카드는 기본이 접힘이다. 접힌 상태에서 보이는 건 파일 경로와 도구 이름뿐. "어느 파일을 만졌다"까진 알겠는데 "**뭘** 만졌다"는 안 보인다. 결국 카드를 열어야 한다. 열두 개쯤 열다 보면 스캔은 실패한다.

그래서 diff에서 **첫 번째 변경 줄 하나**만 뽑아 헤더 옆에 붙였다. `+`나 `-`로 시작하는 첫 줄을 찾아 80자에서 자른다. 그게 전부다.

카드 헤더가 이렇게 바뀌었다.

```
✎ Edit  src/pipeline/runner.py
   + logger.info(f"batch {i} took {dt:.2f}s")
```

이 한 줄이 있느냐 없느냐가 스캔 가능성을 완전히 갈랐다. 첫 변경 줄이 그 편집의 **의도**를 대표한다는 보장은 없다. 실제로 대표하지 못하는 경우도 종종 있다. 그래도 "이 카드는 안 열어봐도 되겠다"를 90%쯤 판정할 수 있으면 스크롤은 살아난다. 완벽함보다 스캔 가능성이었다.

한 가지 걸린 건 파일 전체를 새로 쓴 경우다. 이때는 diff 전체가 `+`라서 첫 줄이 대개 import 문이나 shebang이다. 아무 정보도 못 준다. 이건 아직 안 고쳤다. 새 파일이라는 걸 알면 "새 파일: 42줄" 같은 걸 대신 보여주면 될 것 같다.

## 층 3 — 열었을 때, IDE처럼

카드를 열었을 때 diff가 300줄이면 그것도 벽이다. 세 가지 규칙으로 다듬었다.

첫 30줄만 먼저 보여준다. 나머지는 "더 보기" 토글로 숨긴다. 그리고 `+`·`-`·`@@` 라인을 색으로 갈라준다. IDE에서 diff를 볼 때 눈이 자동으로 찾아가는 그 색.

색을 넣는 것 자체는 정규식 몇 줄이면 된다. 어려운 건 그다음이었다. **문법 하이라이팅(syntax highlighting)까지 갈지 말지**. Python 코드의 키워드에 색을 주고, 문자열은 다른 색으로, 이런 걸 하려면 하이라이터 라이브러리를 하나 끌어들여야 한다. 번들 크기가 커진다. 활동 피드는 로그일 뿐인데 여기에 하이라이터를 얹는 게 맞나 싶었다.

결론은 **diff 자체의 하이라이트만** 넣는 걸로 했다. 언어별 하이라이트는 안 한다. `+`는 연두 배경, `-`는 연분홍 배경, `@@` 헝크 헤더는 회색. 이 셋만 있어도 눈이 훨씬 편해진다. 필요하면 나중에 언어 하이라이트를 얹을 여지는 남겼다 — 파일 경로에서 확장자를 뽑아 클래스 이름은 `lang-python` 식으로 미리 붙여 뒀다. 지금은 그 클래스에 스타일이 없을 뿐이다.

## 남은 것

세 층을 다 지나고도 아직 걸리는 게 몇 개 있다.

같은 파일을 연달아 여러 번 편집하는 경우, 카드가 여러 개 쌓인다. 이건 fingerprint로는 못 묶는다. 입력이 서로 다르니까. 파일 단위로 한 번 더 묶는 뷰가 있어야 할 것 같은데, 그러면 시간 순서가 흐트러진다. 어느 쪽이 더 읽기 쉬울지 아직 판단이 안 선다.

diff 하이라이트를 CSS로만 처리했더니 다크 모드에서 색이 뜬다. 연두·연분홍이 어두운 배경에서 너무 튄다. 이건 그냥 색을 다시 골라야 하는 일이라 미뤄뒀다.

그리고 첫 변경 줄로 미리보기를 만드는 규칙. 새 파일일 때 뭘 대신 보여줄지는 아직 못 정했다. 다음에 이 코드를 열 때 볼 것 같다.
