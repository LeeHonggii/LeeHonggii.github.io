수 MB짜리 마크다운 문서는 로컬 모델의 컨텍스트 윈도우(한 번에 읽을 수 있는 토큰 범위)에 들어가지 않는다. 통째로 넣는 방법이 없으니 쪼개서 요약하고, 요약본을 다시 합치는 수밖에 없었다. 이 글은 그 파이프라인을 만든 기록이다. 중간에 요약 파일이 "정상 생성"됐는데 내용은 에러 문구였던 일도 있었다.

이 글에는 코드를 싣지 않았다. 이번 작업을 대표할 코드 조각을 글에 맞게 고르지 못했고, 지어내서 채우고 싶지도 않았다. 구조와 판단 위주로 쓴다.

## 흐름

실행은 파일 하나를 넘기는 명령 한 줄이다.

```bash
python3 gemma_processor.py summarize_large <file>
```

내부 순서는 이렇다.

1. 원문 해시를 계산하고, 이미 처리한 해시면 바로 종료한다.
2. 마크다운 헤더 기준으로 섹션을 나눈다.
3. 섹션마다 따로 요약한다.
4. 섹션 요약들을 모아 최종 요약 한 편으로 병합한다.

분할 기준을 글자 수가 아니라 헤더로 잡은 이유는 단순하다. 문서가 이미 저자가 나눈 의미 단위를 갖고 있기 때문이다. 글자 수로 자르면 표나 목록 중간이 끊긴다. 헤더로 자르면 섹션 하나가 주제 하나에 가깝게 남는다.

## 큰 테이블은 샘플링한다

헤더로 나눠도 섹션 하나가 컨텍스트를 넘는 경우가 있었다. 대부분 수천 행짜리 테이블이다. 이런 테이블은 전부 넣지 않고 일부 행만 뽑아 넣었다.

이 단계에서 정보가 줄어든다. 최종 요약은 원문 전체를 요약한 것이 아니라 **분할하고 샘플링한 입력**의 요약이다. 요약 속에서 어떤 행이 빠졌는지는 알 수 없다. 이 손실이 요약 품질에 얼마나 영향을 주는지는 아직 재보지 않았다.

## 요약 파일은 생겼는데 내용이 비어 있었다

첫 실행에서는 요약 파일이 만들어졌다. 열어 보니 본문이 "JSON 파싱 실패"라는 취지의 문구로 채워져 있었다.

처음에 의심한 건 호출 방식이었다. 기존 코드는 모델에게 구조화된 JSON을 받는 호출 경로를 썼다. 요약은 자유 텍스트가 나와야 하는데, 이 경로가 JSON 파싱을 전제하니 맞지 않았다. 그래서 요약 전용 호출 함수를 따로 만들어 텍스트를 그대로 받게 했다. 같은 시점에 thinking(답하기 전에 모델이 내부 추론을 먼저 생성하는 모드)도 껐다. 요약에는 필요 없었고, 응답 형식이 흐트러질 여지를 줄이고 싶었다.

이 두 가지를 적용하고 다시 돌리자 정상 요약이 나왔다.

문제는 최초 실패의 원인이 이것이라고 **확정하지 못했다**는 점이다. 로그에는 파싱이 실패했다는 사실만 있고, 모델이 실제로 뭘 돌려줬는지는 남아 있지 않았다. thinking 출력이 섞여 파싱을 깼을 수도 있고, JSON 경로 자체가 안 맞았을 수도 있다. 두 변경을 한꺼번에 적용해서 어느 쪽이 효과가 있었는지도 가를 수 없다. 고쳐졌다는 것만 확인했다.

"파일이 생성됐다"를 성공 기준으로 삼은 것도 잘못이었다. 지금은 생성 여부와 별개로 내용을 확인한다.

## 같은 파일을 다시 요약하지 않기

요약 하나에 로컬 모델을 섹션 수만큼 호출한다. 주기적으로 폴더를 훑는 구조라면, 바뀌지 않은 파일을 매번 다시 처리하는 비용이 가장 먼저 문제가 된다.

그래서 처리가 끝난 파일의 원문 SHA-256을 `original_hash`로 기록해 두고, 다음 실행에서 해시가 같으면 건너뛴다. 수정 시각 대신 내용 해시를 쓴 이유는, 저장만 다시 했거나 복사로 시각이 바뀐 파일을 걸러내기 위해서다. 내용이 바뀌면 해시도 바뀌니 다시 처리된다.

검증은 이미 처리된 28개 파일을 다시 돌려 봤다. 기록상 모두 스킵됐고 전체가 3.7초에 끝났다. 신규·변경 파일만 주기적으로 처리하도록 이 검사를 실행 루프에 연결했다.

## 아직 안 본 것

- 샘플링이 요약에서 무엇을 빼는지 재보지 않았다. 표 위주 문서와 서술 위주 문서에서 차이가 클 것 같은데, 추측일 뿐이다.
- 섹션 요약을 병합할 때 섹션 수가 아주 많으면 병합 입력이 다시 컨텍스트를 넘을 수 있다. 이 경우에 다단 병합이 필요한지는 아직 만나지 못해 확인하지 못했다.
- 요약 품질 자체는 사람이 눈으로 훑어본 수준이다. 정량 평가는 하지 않았다.
- 해시 스킵은 "같은 내용"만 거른다. 한 글자만 고쳐도 전체를 다시 요약한다. 섹션 단위로 해시를 두면 바뀐 섹션만 다시 돌릴 수 있을 텐데, 아직 시도하지 않았다.
