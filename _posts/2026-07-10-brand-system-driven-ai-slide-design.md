처음 AI에게 "B2B 발표자료 슬라이드 만들어줘"라고 시켰을 때, 결과물은 그럴싸했다. 그런데 옆에 있는 우리 회사 자료와 나란히 놓으면 남의 집 옷을 입은 사람 같았다. 파란색은 다른 파란색이었고, 폰트는 낯설었고, 카드 여백은 슬라이드마다 조금씩 달랐다.

문제는 "품질이 낮다"가 아니었다. 품질은 오히려 높았다. **우리 것이 아니었을 뿐이다.**

## 잘못 잡고 있던 가정

한동안 프롬프트에 "우리 브랜드에 맞게", "톤앤매너 지켜서", "일관되게" 같은 말을 추가하는 걸로 버텼다. 결과는 매번 조금씩 달랐다. 어떤 날은 네이비가 살짝 밝고, 어떤 날은 카드 모서리가 뾰족했다.

지금 돌이켜보면 당연한 일이었다. 나조차 "우리 브랜드"가 정확히 뭔지 문장으로 말할 수 없었다. AI에게 해석의 여지를 주는 만큼 결과는 흔들렸다.

방향을 바꿨다. 예쁘게 만들어달라고 부탁하는 대신, **선택지를 좁혀서 줬다.**

## 토큰 테이블 — 해석 여지를 없애기

브랜드 가이드는 보통 PDF나 Figma로 존재한다. 그걸 그대로 첨부하면 AI는 "이 문서에서 영감을 받아" 자기가 이해한 대로 재해석한다. 재해석이 문제였다.

그래서 프롬프트 맨 앞에 토큰 테이블 — 디자인 속성의 최소 단위를 키-값으로 정리한 표 — 을 박아넣기 시작했다.

```
## 브랜드 토큰 (이 값 외 사용 금지)

### Color
- Primary: #181d26   (다크 네이비, 텍스트·헤더)
- Surface: #ffffff
- Muted:   #e0e2e6   (배경 도트, 구분선)
- Accent:  #4f6ef2   (CTA, 강조 텍스트)

### Typography
- font-family: "Pretendard", "Inter", "Helvetica Neue", sans-serif
- H1: 48px / 700
- H2: 32px / 600
- Body: 18px / 400

### Spacing
- 카드 패딩: 40px
- 섹션 간격: 64px
- 그리드 gap: 32px
```

핵심은 마지막 괄호 안의 코멘트다. 색을 나열만 하면 AI는 Primary를 배경에 쓰기도 했다. "다크 네이비, 텍스트·헤더"라고 용도를 못박으니 그 실수가 사라졌다. 값과 함께 **역할을 준다.** 그게 차이였다.

## HTML 캔버스로 고정한 이유

"PPT 만들어줘"와 "1920×1080 HTML 만들어줘"의 차이는 결과물이 아니라 **검수 가능성**이다. HTML은 브라우저에서 바로 열어보고, 눈으로 잡고, 프롬프트를 고쳐 다시 돌린다. PPT는 그 루프가 느리다.

출력 조건도 프롬프트에 규격으로 박았다.

```
출력 조건:
- 단일 HTML 파일, inline CSS만 사용
- 캔버스 고정: width: 1920px; height: 1080px; overflow: hidden;
- 외부 라이브러리 없음 (CDN 불가)
- 배경 패턴 고정:
    background-image: radial-gradient(#e0e2e6 1.3px, transparent 1.3px);
    background-size: 28px 28px;
```

inline CSS 강제가 특히 컸다. 처음엔 AI가 `<style>` 블록에 클래스를 자기 마음대로 정의했다. 슬라이드마다 클래스 이름이 달라졌고, 같은 이름이라도 값이 미묘하게 흔들렸다. inline으로 묶으니 그 흔들림이 사라졌다. 대신 코드가 길어지지만 어차피 사람이 손으로 유지보수할 파일이 아니다.

배경 도트 패턴은 취향이라기보다 계산이었다. 이 하나만으로 "B2B SaaS 같다"는 인상이 생긴다. 그라디언트로 예쁘게 꾸미려는 AI의 기본 습관을 미리 차단하는 장치이기도 하다.

## 금지 목록이 권장 목록보다 강했다

"이렇게 해줘"보다 "이건 하지 마"가 훨씬 잘 먹혔다. AI는 "멋있게"라는 말을 들으면 그라디언트, 그림자, 아이콘부터 얹는다. B2B 자료에선 그게 다 노이즈다.

```
금지 사항:
- 컬러풀한 그라디언트 배경
- 이모지 또는 아이콘 폰트
- drop-shadow 과다 사용
- 브랜드 토큰 외 색상 사용

권장 구조:
- 슬라이드 상단: 헤더 영역 (타이틀 + 섹션 번호)
- 본문: CSS Grid 기반 카드 레이아웃
- 카드 스타일: border: 1px solid #e0e2e6; border-radius: 12px; background: #fff;
```

특히 마지막 줄. "카드 스타일은 절제되게"라고 쓰면 AI는 자기가 아는 절제를 발휘한다. `border-radius: 12px`라고 숫자로 주면 흔들리지 않는다.

## 카드가 들쭉날쭉하던 문제

이건 프롬프트를 아무리 다듬어도 안 잡혔다. 슬라이드마다 카드 3개가 있는데 텍스트 양이 다르면 높이가 제각각이었다. AI는 콘텐츠를 채우는 데 집중하느라 정렬을 놓쳤다.

CSS 한 블록으로 끝났다.

```css
.card {
  display: flex;
  flex-direction: column;
  justify-content: space-between;
  min-height: 260px;
  padding: 40px;
}
```

`min-height`와 `justify-content: space-between`. 이 두 줄이 없으면 카드는 내용 길이대로 자란다. 있으면 짧은 카드도 260px를 채우고, 내부 요소는 위아래로 벌어진다. 프롬프트 언어로 설명할 문제가 아니었다. 규칙으로 박아버릴 문제였다.

## 지금도 안 풀린 것

여기까지 하니 결과물이 "우리 것"처럼 보이기 시작했다. 그런데 여전히 애매하게 남은 게 있다.

하나는 **타이포그래피 위계**. 토큰 테이블에 H1/H2/Body 크기는 박아뒀지만, AI는 종종 슬라이드 하나에 H2를 세 번 쓰거나, 부제로 Body를 굵게 만들어 위계를 흐린다. 이건 값 하나로 못 잡는다. "한 슬라이드에 H2는 하나"라고 규칙을 추가해도 지켜지는 날과 안 지켜지는 날이 있다.

다른 하나는 **일러스트/도식**. 카드와 텍스트는 규격화가 되는데, 개념을 시각화해야 하는 슬라이드는 여전히 손으로 다시 그린다. 아직 프롬프트로 접근할 길을 못 찾았다.

돌이켜보면 결국 한 가지가 계속 반복됐다. AI에게 취향을 맡기지 말고, 취향을 미리 좁혀놓은 상자를 준다. 그 상자를 얼마나 촘촘하게 만들 수 있느냐가 이 작업의 전부였다. 다음엔 타이포 위계 상자를 어떻게 짤지 봐야 한다.
