처음엔 아무 의심 없이 코사인 유사도(cosine similarity — 두 벡터가 이루는 각도로 가까움을 재는 지표)를 썼다. 키워드도, 분류 코드도, 제목도, 발행일도 전부 하나의 벡터에 concat해서 넣고, 내적을 돌리고, 상위 K개를 뽑았다. 숫자가 나오니까 되는 줄 알았다.

검수를 돌리고 나서야 이상하다는 걸 알아챘다. 제목 표현은 비슷한데 완전히 다른 분야 콘텐츠가 상위에 올라와 있었다. 몇 년 지난 콘텐츠가 최신 이슈보다 위에 있었다. "왜 이게 올라왔지"에 답할 수가 없었다. 벡터 내적값이 0.83이었다, 정도가 내가 낼 수 있는 답의 전부였다.

## 신호가 서로 다른 걸 하나로 재고 있었다

문제를 뜯어보니 원인은 뻔했다. 이 네 가지를 같은 공간에 넣은 게 잘못이었다.

| 신호 | 실제 의미 | 자연스러운 유사도 |
|------|-----------|------------------|
| 키워드 | 집합 | 겹치는 원소 비율 |
| 분류 코드 | 계층 트리의 위치 | 같은 노드/부모인가 |
| 제목 | 짧은 자연어 문장 | 표면 표현의 근접 |
| 발행일 | 정수 timestamp | 시간 거리 |

성질이 다른 것들이다. 하나로 concat해서 코사인을 재면 결국 **차원 수가 많은 쪽이 점수를 지배**한다. 키워드 피처가 수백 차원인데 분류 코드는 몇 개 안 되니, 분류 신호는 노이즈 수준으로 묻힌다. 스케일링을 아무리 해도 "이 축과 저 축이 같은 의미"가 되지 않는다.

더 큰 문제는 설명 불가였다. 채용 담당자든 팀원이든 "왜 이걸 추천했나"를 물으면 나는 벡터 곱 하나만 들고 서 있어야 했다.

## 신호별로 따로 재고, 나중에 합치기

바꾼 방향은 단순하다. 각 신호에 맞는 유사도 함수를 따로 정의하고, 전부 0~1 범위로 정규화한 뒤 가중합(weighted sum)으로 결합한다.

```python
# 키워드: Jaccard — 두 집합의 교집합 / 합집합
keyword_score = len(a_kw & b_kw) / len(a_kw | b_kw)

# 분류 코드: 같으면 1, 부모가 같으면 0.5, 그 외 0
classification_score = (
    1.0 if a_code == b_code
    else 0.5 if same_parent(a_code, b_code)
    else 0.0
)

# 제목: 짧은 문장이므로 TF-IDF 코사인
title_score = cosine_similarity(tfidf(a_title), tfidf(b_title))

# 시간: 발행일 차이에 대한 지수 감쇠
time_score = exp(-lam * abs(a_date - b_date))
```

정규화가 핵심이다. 네 개 다 같은 스케일이면, 이후 결합 단계에서 단위 충돌 없이 그냥 더할 수 있다.

## 관점마다 주신호를 바꾼다

여기서 한 발 더 갔다. 추천이라는 게 상황마다 "중요한 게 뭔가"가 다르다. 직무 맞춤 리스트를 뽑을 땐 분류 코드가 제일 중요하고, 사용자가 골라둔 관심 키워드로 추천할 땐 키워드 overlap이 우선이다. 방금 본 콘텐츠와 이어보기용이면 제목·표현의 근접이 중요하다.

관점을 세 개로 나누고 관점마다 가중치를 바꿨다.

```
# 직무 관점: 같은 분야를 강하게
score = (cls*6 + kw*2 + title*1 + time*1) / 10

# 관심 관점: 사용자가 고른 키워드 중심
score = (kw*6 + cls*2 + title*1 + time*1) / 10

# 이어보기 관점: 표현이 가까운 것
score = (title*6 + kw*2 + cls*1 + time*1) / 10
```

일반화하면 이 한 줄이다.

```
final = sum(w_i * s_i) / sum(w_i)
```

가중치를 `0.6 / 0.2 / 0.1 / 0.1` 대신 `6 / 2 / 1 / 1`로 쓴 건 계산 편의가 아니다. 팀에 설명할 때 "이 신호를 저 신호의 세 배로 본다"가 즉시 읽힌다. 소수점 튜닝은 실험 후반에나 필요하고, 초반엔 의도가 드러나는 정수비가 훨씬 낫다. 실험 로그에도 `6-2-1-1`이라고 쓰면 그 자체가 문서다.

## 지표만 봤으면 놓쳤을 것

바꾸고 나서 정량 지표 — Hit@K(상위 K개 안에 정답이 있는 비율), MRR(정답 순위의 역수 평균) — 를 로그 기반 정답셋으로 재봤다. 신호별 합산 구조가 단일 코사인보다 확실히 위였다. 정확한 상승폭은 데이터셋과 시기에 따라 흔들려서, 여기에 숫자로 못박고 싶진 않다. 재현 가능한 조건으로 다시 재는 게 남은 숙제다.

정량 지표만 봤다면 놓쳤을 게 있다. **상위 10개를 눈으로 읽어보는 검수**가 진짜였다. 신호별 구조에선 "분류 일치 + 키워드 overlap 0.7이라 올라왔다"라고 결과별로 설명이 붙었다. 단일 코사인 시절엔 못 하던 일이다. 이 설명 가능성 하나만으로도 구조를 바꾼 값어치가 있었다.

## 아직 정리 못 한 것

시간 감쇠 계수 `lam` 은 여전히 감으로 정한 상태다. 콘텐츠 종류마다 유통기한이 달라서 하나의 값으로 덮는 게 맞는지 모르겠다. 그리고 관점을 세 개로 쪼갠 것도, 실제 사용 로그를 더 쌓아보면 두 개면 충분하거나 다섯 개가 필요할 수 있다. 가중치를 사람이 정한 정수비로 두는 것도 학습 기반으로 넘기는 시점이 언젠간 온다. 그때는 지금의 `6-2-1-1`이 초기값 역할을 해줄 거라고 본다.
