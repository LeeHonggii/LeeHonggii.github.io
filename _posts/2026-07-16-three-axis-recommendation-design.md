추천 화면에 "직업 추천", "관심 추천", "선호 추천" 세 섹션을 얹기로 했다. 이름을 세 개로 나누는 것까진 회의에서 30분이면 끝났는데, 막상 목록을 뽑아보니 세 섹션이 거의 같은 콘텐츠를 뱉었다. 이 글은 그 지점에서 뒤집힌 판단을 정리한 메모다.

## 처음 짠 공식

세 신호를 조합하는 것부터 시작했다.

- S이력: 학습 이력 기반 유사도
- S개인: 사용자가 직접 설정한 관심사·직군 태그 기반 유사도
- S트렌드: 최근 인기·검색 추이

축마다 비중을 다르게 걸었다.

```
직업점수 = 0.6*S이력 + 0.2*S개인 + 0.2*S트렌드
관심점수 = 0.4*S이력 + 0.2*S개인 + 0.4*S트렌드
선호점수 = 0.4*S이력 + 0.4*S개인 + 0.2*S트렌드
```

직업은 뭘 배웠는지가 무겁고, 관심은 트렌드가 세고, 선호는 본인이 찍은 값이 가장 크다. 화이트보드 앞에서 팀 전원이 고개 끄덕이고 헤어졌다. 나도 이 정도면 된다고 생각했다.

## 세 목록이 똑같이 나왔다

QA용 유저 몇 명 뽑아서 상위 20개를 나란히 놓고 봤을 때 처음엔 눈을 의심했다. 겹치는 게 절반이 아니라, 순서만 조금씩 뒤바뀐 수준이었다.

원인을 뜯어보니 두 겹으로 겹쳐 있었다.

하나는, 세 S가 결국 같은 임베딩 공간 위에서 계산된다는 것. 학습 이력이든 관심 태그든 트렌드든 마지막엔 같은 벡터로 눌러 넣어서 코사인 유사도를 잰다. 이 상태에선 앞에 붙는 계수를 아무리 흔들어도 상위 후보가 크게 안 바뀐다. 0.6과 0.4의 차이는 20위 밖에서나 티가 난다.

다른 하나는 후보 풀. 세 축 모두 전체 콘텐츠에서 동일하게 후보를 뽑은 다음, 점수 계산만 다르게 해서 재정렬하는 구조였다. 재료가 같고 소스만 다르면 결국 비슷한 요리가 나온다.

가중치는 1층 문제였고, 진짜 문제는 2층에 있었다.

## 축별 후보 대역

가중치를 만지는 대신, 각 축이 애초에 다른 곳에서 후보를 긁어오게 하기로 했다.

| 축 | 후보 대역 |
|---|---|
| 직업 | 완료한 학습 경로의 **다음 단계** 콘텐츠 |
| 관심 | 최근 N주 이내 급상승 콘텐츠 ∩ 관심 태그 |
| 선호 | 저장·좋아요 콘텐츠와 **보완 관계**인 것 |

선호 축의 "보완"이 이 표에서 가장 오래 붙잡고 있던 칸이다. 유사도로 뽑으면 이미 좋아한 것과 닮은 걸 준다. 그건 선호가 아니라 그냥 취향의 반복 재생이다. 내가 원하는 건 "이걸 좋아한 사람이 다음에 도움받은 것"에 가까웠다. 협업 필터링 신호나 학습 완료 후 이어본 시퀀스를 여기 붙이는 이유가 여기서 나왔다.

## 신호가 없을 때 축이 무너진다

이 구조에도 큰 구멍이 있다. 사전 학습 이력이 없는 신규 유저, 트렌드 데이터가 얕은 틈새 분야. S이력이 0이거나 S트렌드가 균등 분포에 가까우면 세 공식이 다시 수렴한다. 후보 대역까지 무너지면 첫 화면부터 세 섹션이 같은 목록이 된다. 서비스에서 가장 인상이 깊게 남는 순간에 이걸 보여주는 셈이다.

폴백을 규칙으로 박기로 했다.

- 직업 축에 이력 없음 → 직군 태그 기준 인기 콘텐츠로 대체
- 트렌드 신호 얕음 → 관심 축은 전체 카테고리 평균 열람률로 보정
- 선호 데이터 없음 → 선호 축은 관심 축과 같은 자리에서 출발, 데이터 쌓이면 점진 분리

세 번째 항목이 특히 마음에 걸렸다. 처음부터 세 축이 다른 척하는 것보다, 데이터가 없을 땐 "지금은 두 개"라고 인정하고 시간이 지나면서 분리되게 두는 편이 낫다고 판단했다. 이게 맞는지는 아직 모르겠다. 콜드 스타트 구간에서 사용자가 세 섹션이 같은 걸 보는 걸 이상하게 여기는지, 아니면 그냥 넘어가는지 로그를 더 봐야 한다.

## 아직 남은 것

축 정의를 이렇게 정리하고 나서도 재보지 않은 게 있다. 후보 대역을 갈랐을 때 실제로 상위 20개 겹침이 얼마나 줄어드는지, 선호 축의 보완 신호를 협업 필터링으로 뽑는 게 이력 기반보다 정말 나은지, 폴백 규칙에서 관심 축과 선호 축이 언제 갈라져야 하는지. 이 세 개는 다음 주기에서 실측으로 답할 문제다. 지금은 이 글에 숫자를 못 쓴다. 재보지 않았기 때문이다.
