기존 평가 파이프라인의 실행 순서를 처음부터 다시 읽다가, 입력을 바꾸면 어디까지 같이 바뀌는지 궁금해졌다. 지금 파이프라인은 학생이 화면에서 한 조작을 구조화된 이력으로 받는다. 이 입력을 풀이 영상으로 바꾸면 어떻게 될까. 이 글은 그 실험을 구현하기 전에 입력부터 정해 본 기록이다. 영상 처리는 아직 구현하지 않았고, 결과도 없다.

## 로그 경로가 주는 것

로그 경로에서 "학생이 답을 어디에 두었는가"는 추측 대상이 아니다. 화면 요소의 좌표와 종류가 이미 데이터로 들어 있다. 시작 화면에서 답 칸이 어디인지, 그 칸 옆의 글이 열 머리인지 줄 왼쪽 이름표인지도 좌표 거리로 정한다. 판정 AI에게 넘기는 사실도 코드가 먼저 만들어 둔다.

그중 정답과 화면 판독을 맞대는 부분이 이렇게 생겼다. 도메인 용어는 일반화했다.

```python
class Matcher:
    """정답 항목 값과 화면 판독 글을 맞대 일치·불일치·맞댈 수 없음(None)을 낸다 — 판정이 아니라 판정 AI 에 주는 사실. 모르면 None, 틀린 「불일치」를 내지 않는다."""

    @staticmethod
    def board_ok(b, bad, want):
        return all(b.get(u, 0) == n for u, n in want.items()) and all(b.get(u, 0) == 0 for u in "일십백천" if u not in want) and bad == 0

    @staticmethod
    def alternatives(p):
        # 「답 칸1=3 또는 4」 → 「답 칸1=3」, 「답 칸1=4」 — 값 쪽만 「또는」으로 갈린 꼴
        if " 또는 " not in p:
            return None
        alts = [a.strip() for a in p.split(" 또는 ")]
        head = re.match(r"^(.*?[=:]\s*)", alts[0])
        return [a if (head is None or re.search(r"[=:]", a)) else head.group(1) + a for a in alts]
```

`alternatives`의 호출부는 결과 세 갈래를 이렇게 합친다. 후보 중 하나라도 일치하면 True다. 일치는 없고 맞댈 수 없는 후보가 하나라도 있으면 None이다. 전부 불일치일 때만 False가 나온다. 이 파일을 쓸 때 가장 신경 쓴 건 "모르면 None"이다. 판독이 비어 있는데 불일치로 단정하면, 뒤에서 판정 AI가 그걸 사실로 믿고 학생을 틀렸다고 한다.

영상 입력을 생각할 때 이 원칙이 제일 먼저 걸렸다. 로그에서는 값이 없으면 없다고 말할 수 있다. 영상에서는 "안 보인다"와 "없다"가 구분되지 않을 수 있다.

## 영상은 다른 경로다

처음에는 로그를 영상으로 바꾸고 나머지는 그대로 두면 된다고 생각했다. 아니었다. 로그는 이미 구조화된 이력이다. 영상은 프레임 속 픽셀이어서 "무엇이 놓였는지"를 읽는 단계가 한 층 더 필요하다. 지금 코드에서 좌표로 하던 일, 즉 칸을 찾고 옆의 글을 붙이는 일을 영상에서는 비전 모델이 해야 한다.

논의에서 나온 방향은 영상에서 프레임을 추출해 관찰 정보를 확보하는 것이었다. 프레임을 몇 초 간격으로 뽑을지, 변화가 있는 지점만 뽑을지는 정하지 않았다. 구현도 검증도 안 했다. 그래서 이 글은 "프레임 추출이 이렇게 동작한다"가 아니라 "이 입력을 실험하려면 무엇을 모아야 하나"에 집중한다.

## 실험 한 세트의 구성

제안한 한 세트는 세 가지로 이루어진다.

- 문항 이미지
- 정답 이미지
- 학생 한 명이 문항 하나를 푸는 영상

영상은 시작부터 제출까지 편집 없이 녹화한다. 이 조건을 넣은 이유는 편집된 영상에서는 "관찰하지 못한 구간"이 어디인지 알 수 없기 때문이다. 앞의 `None` 얘기와 이어진다. 무편집이면 관찰 범위가 시작과 제출 사이 전체라고 말할 수 있고, 그 안에서 모델이 놓친 것은 모델의 한계로 따로 셀 수 있다. 편집본이면 그 둘이 섞인다.

정답을 이미지로 넣는 것도 로그 경로와 다르다. 지금은 정답 항목이 값으로 정리되어 있어서 위의 `Matcher`가 문자열 규칙으로 맞댄다. 이미지 정답은 먼저 읽어서 값으로 바꾸는 단계가 필요하고, 그 단계의 오류가 판정 오류와 겹칠 수 있다. 이건 실험을 설계하면서 새로 보인 문제다. 아직 분리할 방법을 정하지 못했다.

## 어떤 문항을 모을지

문항은 교과 내용 영역(덧셈, 도형 등)으로 나누지 않고 문제를 푸는 방식으로 나누기로 했다. 입력이 영상이라서 보고 싶은 건 "무슨 단원인가"가 아니라 "화면에서 어떤 행동이 보이는가"이기 때문이다.

- 비교형: 둘을 견주어 답한다
- 분류형: 대상을 묶거나 나눈다
- 구성형: 조각을 모아 하나를 만든다
- 조작형: 도구나 모형을 움직인다
- 표현형: 쓰거나 그려서 나타낸다
- 설명형: 풀이 이유를 말하거나 적는다

유형별로 2~3세트를 모으는 안이다. 여섯 유형이니 계산하면 12~18세트다. 숫자는 탐색용이다. 이 정도로 정확도를 말할 수 있는 건 아니다. 이 규모에서 볼 수 있는 건 "어떤 유형에서 입력이 아예 안 읽히는가" 정도이고, 유형 간 우열이나 평균 성능은 말하지 못한다. 이 구분은 결과를 정리할 때 지킬 생각이다.

## 아직 정하지 못한 것

기존 경로와 비교하려면 같은 학생, 같은 문항에서 로그와 영상이 둘 다 있어야 한다. 그런데 지금 모으려는 세트는 영상 중심이라 로그가 같이 남는지 확인하지 않았다. 둘이 같이 남지 않으면 비교는 "같은 문항을 다른 학생이 푼 것"끼리가 되고, 입력 차이와 학생 차이가 섞인다.

그리고 풀이 영상에서 학생이 말한 소리를 쓸지도 정하지 못했다. 설명형은 소리가 있어야 의미가 있을 것 같은데, 소리를 넣으면 시각 입력만 보려던 실험의 변수가 하나 늘어난다. 이건 첫 세트를 몇 개 녹화해 보고 다시 판단하려고 한다.
