AI 도구가 파일을 고칠 때마다 로그에 편집 이벤트가 쌓인다. 그 로그를 화면에 뿌리는 "코드 변경 내역" 뷰를 다듬은 기록이다. 처음 화면은 삭제 줄은 빨강, 추가 줄은 초록으로 칠한 것이 전부였다. 틀리진 않았다. 그런데 읽히지 않았다.

이 글에는 구현 코드를 싣지 않는다. 저장소에서 가져온 코드가 이 화면의 코드가 아니어서, 함수 본문을 지어내는 대신 어떤 판단을 했는지만 적는다. 함수 이름은 실제 쓴 것이다.

## 같은 편집이 두 번 보였다

가장 먼저 눈에 띈 건 중복이었다. 도구 실행 로그에는 한 번의 편집이 "시작" 이벤트와 "완료" 이벤트로 나뉘어 들어온다. 화면은 둘을 별개의 카드로 그렸다. 편집 한 번이 카드 두 장으로 보이니 변경 내역이 실제보다 두 배 길어 보였다.

두 이벤트는 같은 fingerprint(입력 내용으로 만든 식별 값)를 갖는다. 그래서 fingerprint가 같은 이벤트끼리 묶고, 묶음 안에서는 완료 이벤트를 우선 보여주기로 했다. 완료가 없으면 시작 이벤트를 그대로 둔다. 실행 중이거나 중간에 끊긴 편집이 화면에서 사라지면 안 되기 때문이다. "끝난 것만 보여주는 뷰"가 아니라 "일어난 일을 한 번씩 보여주는 뷰"여야 했다.

## 접힌 카드가 아무 말도 안 했다

카드는 기본이 접힌 상태다. 접힌 카드에 파일 경로와 도구 이름만 있으면 뭘 바꿨는지는 펼쳐 봐야 안다. 카드가 열 장이면 열 번 눌러야 한다.

그래서 `_extractChangePreview()`를 넣었다. 접힌 상태에서도 변경된 핵심 줄을 몇 줄 보여주는 함수다. 목록만 훑어도 "아, 이 함수 인자를 바꿨구나" 정도는 알 수 있다. 어떤 줄을 핵심으로 고르는지는 아직 단순한 편이라, 이 기준은 더 다듬을 여지가 있다.

펼친 상세 화면은 반대 문제였다. 파일 하나를 통째로 쓰는 이벤트가 오면 화면이 코드로 가득 찬다. 긴 코드에는 "더 보기"를 달았고, 펼친 뒤에도 `max-height: 420px`에서 끊어 안쪽 스크롤로 넘겼다. 카드 하나가 페이지 전체를 밀어내지 못하게 하는 장치다. 420이라는 값은 화면에서 눈으로 보고 정한 것이고, 근거가 되는 측정은 따로 없다.

세션 단위로 파일을 묶어 보여주자는 제안도 나왔다. 같은 파일을 여러 번 고친 흐름을 한눈에 보자는 취지였다. 아이디어는 맞다고 봤지만 구현이 끝났는지는 확인하지 못했다. 완성된 것처럼 쓰지 않겠다.

## 색을 두 층으로 나눴다

빨강·초록만으로 부족했던 이유는 배경색이 코드 자체의 색을 덮었기 때문이다. 추가·삭제 여부는 줄 배경으로, 코드의 의미(키워드, 문자열, 주석)는 글자색으로 따로 맡겼다. 두 정보를 한 색에 싣지 않으니 "이 줄이 추가됐다"와 "이게 문자열이다"가 동시에 읽힌다.

편집 diff를 그리는 `_renderEditDiff(..., inp.file_path)`는 파일 경로를 같이 받는다. 확장자를 보고 언어를 정하려는 목적이다.

## Prism이 없었다

구문 강조는 Prism 같은 라이브러리에 맡길 생각이었다. 그런데 실제 실행 환경에서 Prism이 로드되지 않았다. 강조가 아예 동작하지 않았고, 코드는 단색 텍스트로 나왔다. 왜 없었는지는 이 글에서 단정하지 않는다. 원인을 끝까지 추적하지 않고 대체 경로를 먼저 만들었기 때문이다.

그 대체 경로가 `_simpleHighlight`다. 정규식으로 주석, 문자열, 키워드, 숫자를 잡아 span으로 감싸는 가벼운 하이라이터다. Prism이 있으면 Prism을, 없으면 이쪽을 쓴다. 정확도는 Prism에 못 미친다. 템플릿 리터럴 안의 중첩이나 정규식 리터럴 같은 경계 사례는 틀릴 것이다. 그래도 단색보다는 낫다고 판단했다. 로그 뷰어에서 강조가 조금 틀리는 것과 아예 없는 것 중에서는 전자가 덜 나쁘다.

같은 작업의 다른 부분에서 정규식이 멈춘 일이 있어서 이 하이라이터가 마음에 걸린다. 긴 줄이나 특이한 입력에서 `_simpleHighlight`가 느려지거나 멈추는지는 아직 재보지 않았다. 큰 파일 쓰기 이벤트로 먼저 확인해야 한다.

## 남은 것

- 세션 단위 파일 묶음은 구현 여부가 불분명하다. 코드를 다시 열어 확인해야 한다.
- 대체 하이라이터의 성능과 오탐은 측정하지 않았다.
- Prism이 빠진 원인은 찾지 못했다. 대체 경로가 있으니 문제가 가려져 있을 뿐이다.
