콘텐츠 추천 시스템에서 콜드스타트(cold-start, 학습 이력이 전혀 없는 신규 사용자 문제)는 대개 예외 처리로 시작한다. "이력이 없으면 인기 콘텐츠를 보여준다"는 fallback을 달거나, 신규 사용자 전용 파이프라인을 별도로 만든다.

처음에는 나도 그 방향을 생각했다. 신규 사용자가 들어오면 사전역량평가 응답을 읽어서 직무·경력·선호를 파악하고, 그 값을 rule 기반 필터에 넘겨 추천 목록을 만드는 별도 경로. 직관적이고 빠르게 구현할 수 있다.

그런데 그러면 파이프라인이 둘이 된다.

---

추천 엔진의 핵심 로직은 콘텐츠 유사도 계산, 학습자 프로파일 벡터, 가중치 행렬, MMR 다양화까지 꽤 두껍다. 거기에 신규 사용자용 경로를 따로 유지한다는 건 버그가 생길 때 두 곳을 봐야 한다는 뜻이고, 기능을 바꿀 때마다 두 곳을 동기화해야 한다는 뜻이다. 유지 비용이 실제 추천 품질 개선에 쓸 시간을 먹기 시작하는 지점이 보였다.

대신 택한 방법은 단순했다. **사전역량평가 응답을 콘텐츠 1건으로 변환해서 기존 파이프라인에 태운다.**

신규 사용자에게 추천 파이프라인이 "안 된다"고 알리는 대신, 평가 응답으로 만든 가상 콘텐츠를 마치 이 사용자가 수강한 것처럼 시스템에 넣어버린다. 그러면 이력 기반 추천 로직이 그대로 작동한다. 파이프라인은 하나로 유지된다.

---

매핑 구조는 이렇다. 콘텐츠 1건을 표현하는 필드 구조를 먼저 보면:

```python
def _content_row(r: dict) -> dict:
    return {
        'ncs_code': _norm_ncs(r['ncs_code']),
        'related_ncs': _as_list(r.get('related_ncs')),
        'keyword_tags': _as_list(r.get('keyword_tags')),
        'audience_tags': _as_list(r.get('audience_tags')),
        'strand': r.get('strand') or '',
        'sub_category': r.get('sub_category') or '',
        # ...
    }
```

가상 콘텐츠는 이 구조를 그대로 따른다. 사전역량평가 응답이 각 필드로 접힌다:

- **직무** → `ncs_code`. 직무 선택은 표준 분류 체계의 대분류 코드로 변환한다. 세분류까지 특정하기 어려운 경우가 많아 대분류로 고정했다.
- **경력** → `audience_tags`. 온보딩/주니어/시니어 같은 대상 직급 태그로 매핑한다.
- **학습 선호(캐릭터)·6역량 약점** → `keyword_tags`. 텍스트 태그 목록으로 flatten한다.

---

유사도 계산 가중치를 보면 왜 이 구조가 작동하는지 이해된다:

```python
SIM_PRIOR_W = {'kw': 0.4, 'ncs': 0.3, 'strand': 0.2, 'title': 0.1}
```

키워드(`kw`) 가중치가 0.4로 가장 높다. 신규 사용자의 가상 콘텐츠에서 NCS 코드는 대분류 수준이라 해상도가 낮지만, keyword_tags에 담긴 선호·약점 정보는 유사도 계산에서 상대적으로 더 강하게 작용한다.

캐릭터 유형은 추천 축 가중치도 조정한다:

```python
CHARACTER_AXIS_DELTA = {
    '실무 적용가': {
        'job': {'self': 0.04, 'trend': -0.04},
        'career': {'level': 0.03, 'trend': -0.03},
    },
    '트렌드 적응가': {
        'job': {'trend': 0.04, 'level': -0.04},
        'career': {'trend': 0.06, 'level': -0.04, 'self': -0.02},
    },
    '새 분야 탐험가': {
        'career': {'level': -0.06, 'self': 0.03, 'trend': 0.03},
    },
    # ...
}
```

이 delta 값들이 기본 가중치 행렬(`MATRIX`)에 더해진다. "실무 적용가"는 자기계발(`self`) 축을 조금 올리고 트렌드(`trend`) 축을 낮춘다. 별도 로직이 아니라, 같은 행렬에 미세 조정을 얹는 방식이다. 가상 콘텐츠 방식이 파이프라인을 하나로 유지한 덕분에 이 캐릭터 보정도 신규 사용자에게 자연스럽게 적용된다.

---

한계는 솔직하게 남겨둬야 한다.

NCS 코드가 대분류 수준에 머문다는 점이 가장 두드러진다. 이력 사용자의 경우 실제 수강 콘텐츠에서 세분류 코드가 추론되지만, 신규 사용자는 직무 선택만으로 세분류를 특정할 수 없다. 결국 NCS 유사도보다 키워드 매칭이 추천 방향을 더 강하게 끌고 간다.

이게 나쁜 건 아니다. 초기 추천에서 키워드 기반 매칭이 작동하고, 이후 실제 수강 이력이 쌓이면 NCS 해상도도 올라가면서 추천이 정교해진다. 콜드스타트를 "0에서 정상"으로 도달하는 과정의 첫 구간으로 보면 충분히 쓸 만한 출발점이다.

다만 대분류 코드만으로 NCS 유사도를 계산하는 부분이 실제로 추천 품질에 얼마나 영향을 주는지는 아직 정량적으로 재본 적이 없다. 이 부분은 여전히 열려 있다.
