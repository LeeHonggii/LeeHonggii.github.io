AI한테 발표자료 만들어달라고 하면 항상 비슷한 문제가 생긴다. 내가 넣은 내용이 줄어 있다. 표는 사라지고, 코드 블록은 "예시는 생략했습니다"로 바뀌어 있고, 세 문단이었던 설명이 한 줄 불릿으로 압축되어 있다. AI가 요약을 잘하기 때문에 벌어지는 일이다. 요약이 미덕인 작업에서는 그게 장점이지만, 발표자료는 다르다. 원본에 있던 내용은 슬라이드에도 있어야 한다.

이 문제를 어떻게 막을지 생각하다가, 결국 AI에게 요약 권한 자체를 주지 않는 방향으로 갔다.

---

## 요약을 못 하게 막는다

핵심 제약은 하나였다. AI가 Markdown을 슬라이드로 변환할 때, **내용을 줄이는 방향으로만 쓸 수 없게** 한다.

구체적으로는 입력 Markdown의 각 섹션을 슬라이드 하나 또는 여러 장으로만 분할한다. 1:1 또는 1:N. 반대 방향(N:1, 여러 섹션을 하나로 합치거나 일부를 통째로 빼는 것)은 허용하지 않는다.

프롬프트로 이걸 강제하려고 처음에 시도했다. "절대 내용을 생략하지 마세요." 효과가 없었다. 모델이 "생략하지 않겠습니다"라고 답하면서 생략한다. 그래서 방향을 바꿨다. 프롬프트 금지 대신 **출력을 검증**하기로 했다.

---

## Marp를 선택한 이유

슬라이드 형식으로는 [Marp](https://marp.app/)를 골랐다. Marp는 Markdown을 발표자료로 변환하는 도구다. 같은 소스 파일 하나에서 PPTX와 HTML을 동시에 뽑을 수 있다.

```bash
marp deck.md --pptx
marp deck.md --html
```

이게 중요했던 이유는 두 가지다. 편집 가능한 파일(PPTX)과 브라우저에서 바로 볼 수 있는 파일(HTML)을 따로 관리하면 반드시 어긋나는 시점이 생긴다. 소스가 하나면 그 문제가 없다. 디자인 테마도 Marp CSS로 한 번 잡아두면 두 포맷에 동시에 적용된다.

AI의 역할은 Markdown을 직접 생성하는 것이 아니라, 입력된 원문 Markdown을 `---` 구분자로 슬라이드 단위로 쪼개는 것이다. 내용 생성이 아니라 **분할**만 한다.

---

## 검증이 핵심이었다

분할만 허용해도 검증 없이는 믿을 수 없다. AI가 분할 과정에서 슬쩍 내용을 날리는 경우가 생겼다. 특히 코드 블록과 표가 자주 사라졌다.

그래서 변환 후에 자동으로 원본과 산출물을 비교한다. 확인하는 항목은 세 가지다.

- **코드 블록**: 원본에 있던 `` ``` `` 블록이 슬라이드 Markdown에도 모두 존재하는지
- **표**: `|` 기반 Markdown 표가 유실되지 않았는지
- **긴 문장**: 일정 길이 이상 문장이 통째로 사라진 경우 감지

유실이 감지되면 그 슬라이드를 재생성 대상으로 표시하고, 원본 텍스트를 그대로 넣은 폴백(fallback) 슬라이드로 대체한다. 완벽하진 않지만 "AI가 조용히 날린 것"을 사람이 모르고 넘기는 상황은 막는다.

## 실제 사용 흐름

최종 인터페이스는 스크립트 하나로 정리했다.

```bash
python make_deck.py input.md --mode both --design minimal --layout auto
```

`--mode both`는 PPTX와 HTML을 동시에 뽑는다. `--design`은 미리 정의해둔 테마 중 하나를 고른다. `--layout`은 슬라이드 레이아웃 전략인데, 텍스트 양에 따라 1단 또는 2단을 자동으로 선택하는 `auto` 외에 강제 지정도 된다.

이 CLI 뒤에서 실제로 일어나는 순서는 이렇다.

1. 원본 Markdown 파싱 — 섹션 단위로 분리
2. AI가 각 섹션을 슬라이드 하나 이상으로 분할
3. 분할 결과를 원본과 대조해 유실 검증
4. Marp Markdown 조합 및 테마 주입
5. `marp --pptx`, `marp --html` 순서로 렌더링

---

슬라이드 분할 로직에서 아직 완전히 못 잡은 것이 있다. 섹션 경계를 AI가 잘못 잡는 경우 — 예를 들어 코드 블록 중간에 `---`를 넣는 케이스 — 는 검증 단계에서 잡기가 어렵다. 코드 블록이 사라진 게 아니라 쪼개진 것이기 때문에 유실로 감지되지 않는다. 이건 검증 로직을 코드 블록 경계 인식까지 확장해야 하는데, 아직 손대지 못했다.
