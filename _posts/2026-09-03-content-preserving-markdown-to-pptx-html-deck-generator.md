AI한테 발표자료 만들어 달라고 하면 꼭 이런 일이 생긴다. 원본 Markdown에 열 줄짜리 맥락 설명이 있었는데, 슬라이드에는 두 줄로 줄어 있다. 표가 통째로 사라졌다. 코드 블록이 "코드 예시 (생략)" 한 줄로 대체되어 있다. 결과물을 보고 뭔가 허전한데, 뭐가 빠진지 원본이랑 하나하나 비교해야 알 수 있다.

이게 단순히 프롬프트를 잘못 썼다는 문제가 아니라는 걸 깨닫는 데 시간이 좀 걸렸다. AI는 기본적으로 "이 내용을 슬라이드에 맞게 정리해줘"를 "중요한 걸 골라서 요약해줘"로 해석한다. 그게 AI의 기본 동작이기 때문이다.

그래서 이 도구를 만들 때 원칙을 하나 정했다. **AI는 분할만 한다. 요약하지 않는다.**

## 요약 금지, 분할만

Markdown 원본을 슬라이드로 바꿀 때 허용되는 변환은 두 가지다.

하나는 1:1 매핑 — 섹션 하나가 슬라이드 하나가 된다. 또 하나는 1:N 분할 — 내용이 너무 많으면 슬라이드를 늘린다.

삭제는 없다. 요약도 없다. 이 규칙을 프롬프트로 강제하는 건 불안정하다. 프롬프트는 AI가 피로해지면 느슨해진다. 그래서 구조로 강제했다.

AI에게 원본 Markdown을 보여주고 슬라이드 경계(`---`)만 어디에 넣을지 판단하게 한다. 실제 문장을 다시 쓰거나 고치는 역할은 주지 않는다. 슬라이드 레이아웃 선택과 구분선 삽입. 그게 전부다. 문장은 원본에서 그대로 가져온다.

이렇게 하면 AI가 내용을 날려먹을 여지가 물리적으로 없어진다.

## 단일 소스, 두 포맷

PPTX와 HTML을 따로 만드는 건 처음부터 배제했다. 같은 내용을 두 번 생성하면 결과가 달라질 수밖에 없고, 어느 쪽이 맞는지 판단하는 추가 단계가 생긴다.

공통 엔진으로 Marp(Markdown Presentation Ecosystem)를 선택했다. `marp deck.md --pptx`로 PPTX, `marp deck.md --html`로 HTML 덱을 같은 소스에서 뽑는다. 단일 `.md` 파일이 진원지(single source of truth)다.

디자인은 Marp 테마 CSS로 분리했다. 브랜드나 용도에 따라 다른 스타일을 적용할 수 있는데, 각 스타일을 별도 `design.md`로 문서화해서 미리 확인할 수 있게 만들었다. 생성 전에 레이아웃 선택지를 시각적으로 보여주는 단계를 넣은 건 이 때문이다 — 코드를 읽을 수 없는 사람도 결과를 예상할 수 있어야 한다.

HTML 출력은 Marp 기본 출력을 그대로 쓰지 않았다. 기본 HTML은 고정 뷰포트 기준이라 화면 크기에 따라 레이아웃이 깨진다. 별도 반응형 템플릿을 씌워서 모바일에서도 읽히게 했다. 슬라이드 단위를 `<section>` 태그로 유지하면서 CSS Grid로 흘러가게 구성했다.

## 유실 검증 단계

생성 후에 원본과 결과물을 자동으로 비교하는 단계를 파이프라인에 넣었다.

검증하는 항목은 세 가지다. 코드 블록이 산출물에 남아있는지, 표(Markdown table)가 변환 과정에서 누락되지 않았는지, 원본에서 일정 길이 이상인 문장이 결과물 어딘가에 존재하는지. 마지막 항목이 가장 노이즈가 많다 — 슬라이드가 문장을 분할하면 원문 그대로 존재하지 않기 때문에 오탐이 나온다. 이건 아직 완벽하게 처리하지 못했다.

코드 블록과 표 유실은 거의 확실하게 잡힌다. 이 둘이 가장 자주 사라지는 항목이기도 하다.

파이프라인을 CLI 형태로 묶었다.

```
make_deck.py <input.md> --mode both --design <style> --layout <layout>
```

`--mode both`가 PPTX + HTML을 동시에 뽑는다. 검증 실패 시 어떤 항목이 누락됐는지 stdout에 찍고 exit code로 CI에서 잡을 수 있게 했다.

## 아직 미결인 것

슬라이드별 레이아웃 오버라이드 — 특정 슬라이드만 2단 레이아웃으로 바꾸거나 코드 전용 배경을 쓰고 싶을 때 — 를 어떻게 표현할지가 깔끔하지 않다. 지금은 Marp의 HTML comment directive(`<!-- _class: code-slide -->`)를 직접 원본 Markdown에 넣는 방식인데, 이게 원본 Markdown을 오염시킨다. 슬라이드 생성용 메타데이터와 내용을 같은 파일에 섞는 게 맞는지 아직 결론을 못 냈다.

긴 문장 유실 검증 오탐 문제도 마찬가지다. 슬라이드 단위로 분할된 텍스트를 재조합해서 원본과 퍼지 매칭하는 방향을 보고 있는데, 구현 복잡도 대비 실용성이 얼마나 될지는 써봐야 안다.
